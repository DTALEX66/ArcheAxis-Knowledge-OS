# AAOS 2026-11-12 前端、产品旅程与设计交接审计

性质：**审计事实 + 架构/设计提案，未替代 Owner 规范，未执行产品重构**。基线：本地 `main`，`157ee1db401bc4c101ad73309159eca7d09abc9a`；接手已有活动指针、唯一执行记录及 OpenMAIC staged probe 修改，均不由本附件改写。行号对应本轮读取的源码。本文是同日综合审计的细节附件，不是第二执行队列。

## 1. 结论与审查边界

**推荐保留 Tauri/React、Core、草稿与对象会话底座，在现有栈内重整外壳和学习域；第一优先是让已有教学后端成为连续可用的产品。** 现状并非只有页面或 mock：普通文档、研究、关系、表达、学习记录、AI 资产与纠正复测已有真实消费者。最突出的问题是新教学能力没有穿过正式桥接和呈现层、旧页面组织仍主导任务体验，以及记录身份和实际学习内容的层次不够清楚。

实际审查：正式 `frontend/src` 的路由/外壳/文档/阅读/研究/学习/AI/画布/恢复/主题，`src-tauri` 正式桥接和复用关系，相关合同、测试源码、现行规范及 2026-11-02 设计建议。全量文件列表用于定位，生成类型与资源表按相关消费者抽查；没有逐行审查全部测试、全部上游快照、旧 Avalonia、全部历史视图，也没有启动应用、重新截图、运行旧测试/构建/实验或做真人可用性测量。导航成本、性能与可用性影响注明为源码推断，不能当本机交互实测。

已读取任务附件正文与 A—D 附录。规范基准为 `AUTHORITY.md` 第0节、`PRODUCT_IDENTITY_V2.md` V2.3、`CLOSED_LOOP_DEFINITION.md` V3、活动指针所选 Owner 决定及交接；冻结包标题和旧设计图不作当前通过证据。供体最新后端状态以综合报告的后端附件与原始回执为准。

## 4. 三条旅程与对象贯通

| 旅程 | 已有链路 | 缺口与拟定下一步 | 验收归属 |

| 人的完整学习 | 资料/原件→阅读编辑→知识→course_from_knowledge/course_get/course_render→learning_reference/assessment→作答/复习；Teaching记录可保存；外部manifest可保存和记录attempt | 新教学接口→桥接→内容舞台；同一活动保留资料/目标/讲解/attempt/反馈/续做；独立掌握判断另列 | CL-01/02/05/07；J1/J5/J6；X3/4/5/7/8 |
| 比较纠错 | PublicResearchPanel→Core公开检索/保全→CanonicalResearch研究文档、citation和support/oppose/conflict→回阅读源→保存修订 | 把“识别是否忠实”与“内容主张是否可靠”分开呈现；同文同版判断、全文/摘要、差异处理与四消费者当前性并列；减少重复选对象 | CL-01/03/07；J2；X5/8 |
| AI 知识复用 | AiAsset候选Document→逐项评审/采用→packet/grant→MachineAnswer→纠正candidate→新授权retest→task/评价读回 | 改为内容优先的资产详情与使用时间线；保留原问题、原回答、纠正、独立复测关系；成功执行/质量评价/采用效果三者分开；自动提炼尚须逐模块确认 | CL-01/06/07；J4；X5/8 |

共同引用是已保存对象及固定版本，不复制正文到每个页面再当新真值。研究、学习和AI可以创建各自派生记录；它们引用同一材料，不要求领域合并成万能Document表单。普通笔记、外部实践文字和未核实研究可保存；知识接纳与AI授权是特定操作，不前移成每次编辑的前置。

## 5. 推荐外壳与状态责任

这是一份布局提案，不修改现行 page ID、业务库或已存偏好。

| 区域 | 唯一职责 | 默认与展开规则 |
|---|---|---|
| 全局导航 | 工作台、资料与知识、研究与比较、学习与表达、AI助手 | 一条左导航；960px以下变可关闭抽屉；资源/导入导出/设置在底部辅助区 |
| 当前集合/目录 | 当前入口的文件夹、专题、课程目录或资产集合 | 仅需要切换对象时展开；不会重复五入口；阅读/课堂可收起 |
| 对象标签 | 已打开对象，标明草稿和只读 | 复用Dockview与写租约；同对象从多入口打开时定位已有标签；页面工具不占一个对象标签 |
| 主内容 | 阅读、编辑、比较、课堂、作答或资产详情 | 占主要面积；比较才双栏；课堂先舞台，题目出现后占明确作答区 |
| 检查器/助手 | 当前对象的来源/版本/关系/问题/助手 | 默认关闭；由操作打开一个辅助面板，不同时并排占三栏；切换时保留未提交文字 |
| 任务抽屉 | 转换/模型/生成/取消/失败/未知请求 | 收起显示简短状态；打开后按对象分组，诊断ID折叠；不新建独立任务队列 |

采用渐进展开用于低频细节、IDE式标签用于同时处理多个对象、知识库式阅读用于内容、教学舞台用于讲解与练习。这里是交互原则取舍，不声称照搬任何外部产品的当前实现。已有 `docs/design/20261102-ui-research/界面调研与重设计方案.md` 的官方来源调研可继续复用。

状态责任：Core保存Document/Knowledge/AiAsset/活动/attempt/event；ui_state保存工作草稿与有限续做位置；Dock layout保存面板布局；localStorage只存非业务外观偏好。异步请求仍按原request/event身份恢复，未知结果先读回，不自动重发。课程播放位置不能当学习完成，学习完成不能当掌握，资料新版本不能替换历史引用。

响应与可访问细则：

- 1440px以上允许目录+内容+按需检查器，仍默认内容优先；960—1439px最多一辅助栏；640—959px单主区，比较用“原文/对照”可切换视图；短窗口保留输入、保存和任务状态，不用整体缩小字体藏溢出。断点是本提案，须按真实内容验收。
- Ctrl+K搜索、清楚的标签焦点顺序、Esc逐层关闭并回触发点；不覆盖文本编辑快捷键。现有App对`compositionstart/end/isComposing/AltGraph`已有保护，必须继承；新增输入组件在中文候选期间不得提交/切页。纯组件测试不能替代Windows IME验收。
- 加载分别显示“正在读本地内容/正在取得外部结果”；空列表与读取失败分开；有成功数据时保留它。离线读写继续，联网比较/生成按钮给出具体依赖状态。已提交但未知结果保留草稿、原请求及查询动作。
- 对比状态用文字+图标；焦点框清楚；动画服从 reduced-motion。无来源不能编造引用；可生成未核实候选，不能显示为验证通过。
- 位置恢复键建议复用 `{workspace_id, restore_epoch, object_ref, activity_id?}`，值仅含阅读anchor/滚动、场景ID、播放时间与返回目标。活动版本不匹配时提示“历史进度”，不把旧成绩带到新版本。此为合同增量提案，不另建状态库。
