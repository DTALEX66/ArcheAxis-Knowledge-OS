## Design guidance for the R05 API wiring (learned the hard way)

To make FSRS the real default, `record_review_keyed` must take the interval as a
parameter (`Option<i64>`, `None` = scheduler unavailable) instead of computing the
ladder internally. Do it by **parametrizing the existing keyed path** — an enum
(e.g. `Ladder` vs `Explicit(Option<i64>)`) plus one private helper that both
public entry points call — rather than by copying the dedup/insert logic into a
second function: two copies of the event-key dedup rules will drift, and the
duplicate-key/conflict semantics are exactly what R2 EVENT-01 pinned down. Keep
the observable contract explicit: a replayed retry returns the original receipt
(`-1`), an unavailable scheduler records the event with `next_review` NULL, an
explicit `schedule: unavailable` marker and its own sentinel (`-2`), and the
conflict/missing-key errors stay unchanged.

Attempted-and-reverted (no code landed) while doing this with a tight budget: an
insertion that left a duplicated legacy body in `learning.rs`. The tree was
reverted to the verified `469f54a` state instead of committing a half-refactor;
prefer editing the file with the edit tool over scripted line surgery.

7. Do not hash a live SQLite database to prove it was untouched unless you opened
   it read-only: opening read-write checkpoints the WAL and rewrites the file.
8. Replacing a SQLite file means moving its `-wal`/`-shm` aside too.

12. Do not freeze measured totals in a gate record: a commit that adds owned files

13. Writing a JSON record with Python's default text mode on Windows produces CRLF,

14. The shipped `verify_package.py` hashes all 23 manifest entries, but two of them

## Update — round 67 (R15/F04: media types follow the file, not the kind)

The format matrix said the Core announced every image job to the OCR worker as
`image/png` while the worker accepts five formats. That was true and it is now fixed
rather than documented: `claim()` reads the source's `original_name`, derives the
media type from its extension through `attempts::media_type_for_name`, and requires
the result to be one the route's worker accepts, checked against a new
`ROUTE_MEDIA_TYPES` table that mirrors the transport's own declared sets (text 7
types, pdf 1, image 5).

A file whose type the route cannot accept - a PDF payload named `shot.png`, or a text
job whose file is `shot.jpg` - is refused with a `MediaTypeNotAccepted` error that
lists the accepted set (HTTP 400) and, importantly, leaves the job `queued`. A name
with no extension we are willing to name (`clipboard`, `scan.dat`, `input.bin`) is
refused too, because guessing is exactly what the old pinned value did. The caller
must say what the file is.

ten kind/name/media cases, the derivation table, the mismatch refusal and the unnamed

## Update — round 68 (R15/F01: the text route reports what it can really derive)

Round 67 made the Core tell a worker what a file is. Round 68 makes the text route
use that: with the declared media type in hand, the worker reports the structure it
can genuinely derive, in `loss_receipt.params.format`.

- markdown: headings with level, line number and text (headings inside a code fence
  are excluded), plus wiki-link, embed, markdown-link, code-fence, list-item counts
  and frontmatter detection;
- CSV/TSV: delimiter, row count, column count, header, and **ragged row count**;
- JSON: parse result with top-level type, key count and nested depth;
- XML: parse result with root tag, element count, child count and depth.

### The unseen evaluation (ledger row `R11e`)

`scripts/probes/r11_unseen_evaluation.py` authors five documents, **proves they are unseen**
(their distinctive values and opening sentences appear in no tracked file — checked against
every tracked file's text, not assumed), then runs the whole loop against a real Core:
import → machine candidate → human `accepted` → one closed-form query per document → human
`modified` correction of one measured value → ask the same queries again → ask one further
query **for the first time after** the correction.

Two measurement bugs were found **in the probe** and fixed there; neither was a product
finding, and reporting either as one would have been wrong:

1. The first version scored a hit by the **source name** in the search response. That
   response carries no source name at all: items are `{knowledge_id, status, head, active}`.
2. The second version scored a hit by the **distinctive token appearing in the head**. The
   Core returns `substr(body,1,60)` as the head (`crates/archeaxis-domain/src/search.rs`),
   so a value 78 characters into a document can never appear in it.

The criteria now in use: a hit is **a returned head that is a prefix of the expected
document's body**, and query terms are compared as **whole tokens**, because the search runs
an FTS5 `MATCH`.

Measured, with the receipt in `.project-local/runs/r11-unseen-receipt.json`:

- 3 of 5 documents came back, both before and after the correction.
- Both misses are **explained by the query's own vocabulary**: `dating` and `distance` are
  not tokens of those documents (the documents say "dated" and never say "distance").
  **Zero unexplained misses.**
- The correction is observable in the index: the same all-terms-present query returns a head
  reading `…retreated 640 metres…` before the correction and `…retreated 705 metres…` after
  it, and the superseded value stops being returned.
- The query asked for the first time after the correction returns nothing, because `revised`
  is not a token of the document.
- **Finding for the owner, not for the repository to settle:** retrieval is a literal-token
  AND with no stemming, so an inflected query returns nothing for a document the corpus
  holds. The probe signs **no PASS for retrieval**, and it never measures ranking.

### Two real defects the full suite found (ledger row `R15v`)

1. **The HTML worker refused real markup.** The refusal added in round 84 to stop a renamed

### Pitfalls added to the list (do not re-diagnose)

22. **A regex allow-list is not "is this HTML".** Any predicate written as a list of known

23. **Flushing at `close()` widens what counts as "has content".** Any predicate like

25. **A record that states numbers must have them re-derived somewhere.** "As of commit X"

### The two boundaries, both re-enforced by the Core

1. **No human review action exists on the surface.** Acceptance, rejection, deprecation and

   being silently ignored.
2. **An outcome is a measurement.** `unmeasured` is first-class, a failed task must say why,

## Update — round 89 (R15/F05: the reading order is modelled, and reported)

The matrix had recorded one plain sentence for text PDFs: *there is no reading-order or
column-layout model*, so a two-column page was projected in whatever order the engine
returned. It now has one.

### What the worker does now

The projection's reading order is decided by the worker and **reported as a fact with its
reason**, once per page:

- the model is **one vertical gutter with text on both sides, then column by column and top
  to bottom**;
- it **may only reorder**. If the reconstruction would change *which lines the page holds*,
  the model refuses itself, keeps the engine order and records why;
- it **stands down entirely** when the engine text carries blank separator lines, because a
  line-level reconstruction would not carry those;
- a **single-column page comes back exactly as the engine gave it**, so the model costs
  nothing where there is no layout to model.

### The measurement that changed the design

The first version ordered **blocks**. It would never have applied to a real two-column page,
and the reason is measurable: on an 800x600 page with six runs inserted left, right, left,
right, the engine returns **three blocks that each span both columns** — so block-level
ordering cannot see the columns at all. The **lines inside** those blocks carry the real
per-column boxes. The model was rewritten at line granularity because of that measurement,
not because of a guess.

### The record patch was surgical on purpose

One gutter, so it reads two-column pages rather than an arbitrary layout; blocks are still
