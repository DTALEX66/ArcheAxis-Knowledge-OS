### 给 DeepSeek 的前置必须具体，不能只说“协议冻结了”

每个可下发子卡必须附：实际输入/输出样例、现存符号或新增接口精确定义、状态/错误/权限边界、允许修改文件、一个合法与一个非法案例、可运行验收命令、GPT 接回的集成责任。只有这些齐备且对应关键实现已验证，才能标 READY；不得把五张卡一次性泛泛放行。

- DS11：GPT 提供一个真实 Core→非文本 worker→持久化→输出读回的参考链；资源上限与终态策略不能让批量包装层自行决定。
- DS12：GPT 做主工作台、全局主题/资源唯一入口与服务绑定；DeepSeek 根据批准组件 API 扩页面/状态，不自行改产品视觉或共享资源。
- DS13：GPT 决定 ID、版本、关系、原件、学习记录映射与失败原子性；DeepSeek 只按固定契约造合成样本和字段对照。
- DS14：GPT 决定用户接受与事实支持的区别、审核权、撤销传播、FSRS 时间/掌握证据；DeepSeek 扩已有接口的确定性正反例。
- DS15：GPT 做完整候选运行验收；DeepSeek 装配实测支持矩阵/限制/使用说明，不重建候选或自行发布。

### GPT 不应继续反复承担的低难度工作

关键词/路径批量核对、已经裁定目标的链接修正、固定 fixture 扩充、独立指标复算、批准后的组件铺设、只读受限清单、运行已给出的定向命令、回执补字段都留 DeepSeek。GPT 做接口/领域/风险裁决和差异审查，不以反复写治理文档或统计测试数量代替用户可用功能。
