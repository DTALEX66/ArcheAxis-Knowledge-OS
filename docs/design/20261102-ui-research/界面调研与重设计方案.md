# 星环知识系统：界面调研与重设计方案

日期：2026-11-02（Asia/Shanghai）｜性质：**研究与设计建议，非已实现或已验收功能**。

## 推荐结论

重设计共同外壳、导航和关键任务页面，复用现有业务消费者、Core API、对象与版本、来源、草稿保护、主题和小栖资产。允许视觉和布局发生明显变化，但不因重设计新建第二个知识库或把两套供体的完整站点套进去。

核心体验是：**一份资料或一个主题，可以按任务切换阅读、研究、关系、课堂、练习和笔记；内容身份与来源保持一致。** AI 不只是一条聊天栏：AI 工作中提炼出的知识候选也应有独立的采用、授权、使用、纠正和复测路径。

本方案参考了项目的[产品身份](../../../docs/truth/PRODUCT_IDENTITY_V2.md)、[闭环定义](../../../docs/truth/CLOSED_LOOP_DEFINITION.md)、现有前端代码、2026-10-27 的空工作区截图、用户提供的知识星系视觉参考，以及仓内 DeepTutor 1.7.1 / OpenMAIC 1.3.0 原版截图与部分源码。旧截图不等于当前实时界面；没有启动当前产品，也没有真人可用性试验。

## 建议的信息架构

保留现行五个稳定入口及既有页面 ID／深链；资源、设置和全部能力作为辅助入口。一个操作只在一个层级承担主职责：

1. **工作台**：继续上次工作、待复习、最近资料、导入。知识星图作为可切换的探索模式，不用虚构数字填充空白。
2. **资料与知识**：同一对象切换原件、正文、笔记、关联和版本；选中内容可打开来源核对或助手。普通保存不以联网或事实审批为前提。
3. **研究与比较**：围绕问题并列展示来源观点、自己的判断和待解决问题；来源用于回查、比较与纠错，不自动赋予某来源唯一权威。
4. **学习与表达**：资料或主题 → 可编辑学习目标／大纲 → 阅读或课堂 → 练习与反馈 → 复习／独立复测。课堂场景可包含讲解、测验、互动和项目实践；每项按真实接入情况显示可用状态。
5. **AI 助手**：提供与当前对象相关的对话，也要有独立的 AI 知识候选、采用／授权、使用、纠错和复测入口；不将外部原始会话搬入业务知识库。

顶部菜单负责低频命令；一种全局导航负责切换入口；对象标签只表示已打开对象；页内切换只服务当前任务。不要让四层导航分别重复一遍相同入口。来源、目录、关系和小栖可共用按需展开的辅助区域。

## 视觉、窗口和状态

- 本次概念使用 Owner 后继纠正过的**黑／炭灰／灰白**基底、白色主要动作、克制的局部暖色光；不沿用本轮早先两张偏蓝草图。星系／神经核/扇出关系源自实际参考，但应由真实对象驱动，阅读正文保持安静清晰。
- 保留当前五种可切换主题和现有小栖形象；生成图没有替代人物素材。允许关闭或降低非必要动效，并考虑系统减少动态效果偏好：[W3C 指南](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions)。
- 用同一套流式布局分别检查普通非最大化窗口和 1920×1080 满屏；小窗口优先保留正文、课堂舞台和输入，辅助区折叠；极小窗口整体缩放仍须真实实现和验证。微软的[响应式桌面导航](https://learn.microsoft.com/en-gb/windows/apps/develop/ui/controls/navigationview)可作设计参考，不把其默认断点直接当成 Owner 指定值。
- 空、加载、离线、未接入、失败、来源已更新和结果未知均需可理解的真实状态。课程、互动和 AI 自动评分等不得仅因概念图出现就展示成已可用。

## 重构方式与可复用资产

| 选择 | 优点 | 风险／建议 |
| --- | --- | --- |
| 只调整颜色和间距 | 成本低 | 导航、任务顺序和重复区域仍可能存在，不足以解决结构问题。 |
| **重构共同外壳和关键流程，复用 Core 与业务组件** | 用户能明显感到更清晰，又保留数据、历史身份与已有业务成果。 | 推荐。先用单个“资料→课堂→练习→回查”场景验证，再逐步迁移其余入口。 |
| 全部重写客户端与存储 | 视觉自由 | 数据迁移、回归和双重写入风险大；目前没有证据表明必须重做存储。 |

当前 [frontend/package.json](../../../frontend/package.json) 已有 Tiptap、Dockview、Radix、PDF.js 和 Lucide 等；先核对当前消费者是否满足需求，再决定替换或增加依赖。[React Flow](https://github.com/xyflow/xyflow/blob/main/LICENSE) 与 [Excalidraw React](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/package.json) 可作为节点图／自由画布的 MIT 候选，必须评估持久化、性能、键盘操作和与 Core 的适配。[BlockSuite](https://github.com/toeverything/blocksuite) 为 MPL-2.0，且有自身块与协作模型，不能默认直接替换现有存储。[tldraw 当前许可证](https://github.com/tldraw/tldraw/blob/main/LICENSE.md) 对生产使用有限制，不能因源码可见就当成无条件免费复用。具体版本、素材及依赖须另核。

## 三张图的正确读法

本轮根据上述研究生成的三张黑灰白概念图，分别示意[工作台](01-工作台概念.png)、[围绕资料的思考桌](02-知识思考桌概念.png)、[课堂舞台](03-沉浸课堂概念.png)。它们是**构图讨论材料**，不是可操作原型，也不是三套必须分离的产品；可组合其优点。图中的傅里叶示例、关系、学习进度和题目均为合成示例。三张生成图各为 1672×941 像素，并非 1920×1080 原生应用截图或窗口适配验收。

生成图仍有缺点：工作台图的部分导航可能重复；思考桌图的星图占比偏大；课堂图的作答区尚不足以表现完整输入、反馈和状态。因此不能直接按图施工。真正的设计需要继续覆盖资料导入、研究、AI知识候选、错误和小窗口等场景。

## 后续实施与验收建议

先完成设计评审和可访问交互原型；前端构建的启动时机仍由当前任务与 Owner 安排决定。实现时先打通真实数据支撑的资料→课程→练习→回查一条切片，再扩展五入口；保留现有页面兼容及恢复路径。对默认小窗口与满屏分别检查输入空间、键盘、缩放、可折叠面板及实际来源跳转。图像、源码、模拟测试、真实 Core、真实模型、安装态与 Owner 接受分别记录。

本轮后端另补三条 Tauri→Core 固定命令；合同与安全相关测试 23 项通过、生成类型和 Rust 语法检查通过。新增 Rust 测试尚未编译执行，不能据此宣称两套供体已完整并入；超时和取消后的未知结果边界仍需处理。
