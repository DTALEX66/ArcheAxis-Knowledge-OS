# ArcheAxis：全仓覆盖核对、首次可用根因与已实施修复

日期：2026-09-15。活动包仍为 `docs/authority/taskpack-0912-r5/`；本文件是 X00/X01/X03/X13 的修复记录与接续说明，不另建母任务包，不修改冻结任务正文，不代签 Q00/Q01。

## 1. 结论与责任

当前默认产品入口还不能完成空库首次闭环。这是可定位的产品集成、迁移与验证问题；没有证据证明必须推翻整个项目，也没有证据把根因归给模型品牌或全局插件。

此前“最快闭环”反复没有交付的工程原因：

1. 原件导入、worker 执行、候选接受、学习题目生命周期各自存在部分代码，但默认界面没有把它们串起来。
2. DeepTutor 早已决定采用，实际仍停在可启动、路由与权威适配未接完；运行一个独立第三方页面没有让用户用上 ArcheAxis 数据。
3. legacy 四库、学习页面和恢复能力未完整迁移到 vNext，旧版成果没有变成新默认入口的等价行为。
4. 测试的成功边界错误：`run_journey` 可在空搜索后写入 `correct=True` 并返回成功；这不能证明真人学习，也不能证明导入资料成为知识。
5. CI 的历史依赖、平台路径、Rust workspace 有真实错误；另一方面，部分 vnext-ci 成功只覆盖局部，不能抵消主 CI/nightly 失败。
6. 文档与规则存在过期入口。文件归属 100% 只证明目录分类，不证明已迁移、已融合或可使用。

此次已实际修改源码、补测试并建立可回滚补丁。没有完成 Windows 可见界面闭环、Green 部署或完整发布验收，不能说“现在已经能用了”。

## 3. 历史与新规划的统一解释

项目名称锁定 ArcheAxis。历史中文品牌名、旧仓库名仅作来源标识，不作为重新命名的理由。

| 保留的产品目标 | 当前实现方向与承接 |
|---|---|
| 外部资料→识别→转换→来源与证据→知识 | Rust Core 接原件与事务，成熟 Python workers 计算；用户可查看正文、损失、出处并接受候选 |
| 人类学习增强 | 阅读、提取练习、讲回、延迟无提示测验、提示记录、FSRS、迁移测试；近期不能缩减成只有卡片ID和“答对”按钮 |
| 机器使用与反馈 | 同源知识执行真实任务，结果独立检验，修订后旧方法失效；机器能力不能从人的学习结果推断 |
| 个人知识 | 经验、定义、假说可保存和学习；个人接受与外部事实核查分开，离线和无模型不能挡住保存资料 |
| 正式技术边界 | C#/Avalonia 宿主；Rust 唯一新库写者；Python workers；允许复用 Web/TS、本地浏览器先交付 |
| 旧成果 | 作为行为供体与迁移来源；禁止旧 Python writer 与新 Rust writer 双写同一活动库 |
| 可视化与知识宫殿 | 学科图表、动画、仿真、图谱、2D/3D/VR/AR、空间记忆、开放导出、多端等保留；冻结实现不等于删除需求 |
| 运行通道 | TEST/GREEN/STABLE 隔离；Green 是滚动运行投影，Git 为源码真值；旧可恢复版本保全 |
| 外置资源 | 沿用已有共享资源登记与项目绑定；Windows工具不在PATH不等于没安装。当前Linux无法读取用户D盘登记 |
| 清理 | 先修生产者与输出位置，保全唯一资产，再按精确授权清单处理可重建数据；不能因名称或同hash删用户资料 |

### 四库定义已找到

`shared/workspace_manifest.py` 与现有 workspace manifest 合同定义了：

| 稳定ID | 职责 |
|---|---|
| `source_archive` | 原始资料归档 |
| `evidence_ledger` | 证据与知识账本 |
| `human_learning_vault` | 人类学习资产 |
| `ai_asset_vault` | AI资产 |

上轮“第四库职责未知”应更正为“旧版明确存在 AI 资产库，新版承接仍需实现”。用户自选中文路径、四库独立绑定、程序目录外配置仍需正式入口验收。

### 二进制历史包不能拿来冒充现产品

历史 MCS Phase5 ZIP 明确以研究候选→审核→知识版本→学习资产→确定性练习→机器候选为演示纵切，并附独立SQLite与启动入口。它可以提供事件与交互设计参考，但“填充合格示例并提交3次”不能成为当前真人掌握或机器能力的证明；不得恢复为第二个权威写库系统。
