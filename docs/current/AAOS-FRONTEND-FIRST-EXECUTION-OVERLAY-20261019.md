## 1. 继承关系、优先级与执行规则

- 闭环含义只读[唯一闭环定义](../truth/CLOSED_LOOP_DEFINITION.md)，不以本次Stitch接入删减其七个必备维度或改为仅做视觉样板。
- 任务来源继续使用`docs/taskpacks/aaos-ui-first-20261009/`的TASKPACK、TASKS、PAGE-PLAN、FREEZE-REGISTER，原UF/CB/S/G/H/O等ID及后端合同继续有效。UI-P与BE-P是本覆盖的实施／检查分片标识，需在唯一执行记录映射回原任务，不能创造第二套产品能力登记。
- 本期范围是当前已授权产品的所有页面、共用壳、菜单、弹层与状态；长期冻结能力只保留规划／未接入展示，不因全面UI审查启动其运行实现。V01、FT01—04及六项增量的冻结仍按活动指针解析。
- 执行顺序：现场接续与已有失败定位／审计漂移修复→全量Stitch UI-P01—24与BE-P01—15并行接通→同候选CL-01—07/J1—J6整体验收与授权交付。先复用现有接口；真实缺口补合同与实现后回接UI，不能写假成功或直接写库。共享checkout一个writer；权限不足时各组只写独立提案目录，由协调者串行接收和统一验证。
- 按源码／现有回执逐项辨别已实现、需要修复、缺失、待验收，复用既有组件，不能把清单全当未实现重做。只运行相关回归，阶段终验再跑规定门禁；不每改一处CSS就重建整套产品或重复运行模型。
- 独立读审、规范查询、证据分析可并行；写同一checkout只能一个writer，独立writer使用各自已授权隔离worktree。协调者统一合并和验证；不擅改Agent模型/provider/推理配置。
- 界面缺陷必须有页面／状态／视口、实际截图、复现、预期、实测、根因或待核点、修复与回归；截图需实际查看，不用随机点击、无障碍树或测试数替代视觉结论。
