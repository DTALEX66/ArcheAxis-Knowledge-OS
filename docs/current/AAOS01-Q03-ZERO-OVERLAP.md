## 3. **更正我自己**：C 不"薄"

我前两轮把选项 C 称作"**薄**兼容适配层"。**测量不支持这个词**：

**准确的说法是：宽而浅。**

| 维度 | 实际情况 |
| --- | --- |
| **宽** | **61 条**路由都要有对应处理 |
| **浅** | 每条多为**路径重写 + 字段改名**的透传，不需要业务逻辑 |

**我保留对 C 的推荐，但推荐的理由要换** —— 不再是因为"它小"，而是因为：

1. **加性且可逆**：不改 Core、不改前端；
2. **不碰那个有 119 个绿色用例的模块**（B′ 要碰）；
3. **不改 Core 的 `0.1.0-outline` 契约**（A′ 要提前冻结）；
4. 符合 `AGENTS.md` §1 成文的 adapter/sidecar 偏好。

**代价要点明**：它是 **61 条**要维护的映射，**不是小工程**。
