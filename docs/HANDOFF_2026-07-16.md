## 4. 当前真实能力边界

### Contracts

Phase 2 已建立并验证：

- `TaskPackV1`、`ExecutionTraceV1`、`EvaluationV1`、`LessonV1`；
- `SourceRecordV1`、`ClaimV1`、`EvidenceV1`、`ResearchPackageV1`；
- `KnowledgeUnitV1`、`RelationV1`；
- `LearningArtifactV1`、`MasterySignalV1`；
- `MachineKnowledgeUnitV1`。

Legacy 可表示字段必须无损往返；未知字段 fail closed；caller-supplied/legacy-unverified 数据不得自动提升为 verified、approved、published 或 reviewed。

### Runtime

当前真实纵向链：

```text
Goal: read file: AGENTS.md
→ Planner: file_read
→ Permission
→ registered tool execution
→ path + content, non-dry-run Evidence
→ execution/status/evidence Evaluation
→ trace-bound Lesson
```

不支持的 Goal 不得 fallback 为 echo 成功。echo、no-op、preview 和 dry-run 不是成功证据。其他 Goal 仍需逐个增加真实意图和工具证据，不得宣称通用 Planner 已完成。

### Authentication and gateway

- runtime 源码不保存默认管理员 Key；开发、测试和生产凭据必须显式提供；
- Token 签发重新认证管理员调用者，普通用户不能通过 `role=admin` 提权；
- Rate Limiter 对普通读、敏感写和 `/auth/token` 使用独立策略；
- API Key/JWT/匿名 peer 使用不可逆身份桶，不保存原始凭据；
- 双凭据请求 fail closed，认证凭据与 bucket 凭据不能分离；
- 所有仓库拥有的 Uvicorn 入口禁用隐式 proxy-header rewriting；
- 未受信代理头和双凭据早期 400 同样消费 pre-auth 预算并最终达到 429；
- limiter 当前是单进程内存实现，不具备多进程/分布式一致性。

## 5. 当前 TaskPack：通用 Migration Runner；下一项为 Phase 3 集成验收

### 目标

当前候选已把分散的 migration/rebuild owner 统一到一个可注册、可查询、可运维的边界：

- 复用 `shared/migration.py` 已验证的 ledger、backup、manifest、幂等与 offline rollback；
- 已注册 TaskPack SQLite migration、Vector documents/cards shadow candidate 和 FTS documents/cards shadow candidate owner；
- 已提供 operator `status/apply/rollback` 与非交互 CLI，明确 pending、applied、failed 与 rolled-back provenance；
- owner 名称、身份和目标 ownership 冲突 fail closed；
- Vector/FTS activation 只发生在 candidate 完整验证后，失败保留旧活动索引并记录可归因证据；
- FTS operator import 不再触发 configured storage 初始化；TaskPack schema 与 applied provenance 同 transaction 提交；owner lease 阻止并发 switch；Vector 校验 embedding fingerprint 与 canonical source snapshot；
- current-schema fresh TaskPack 的 ledger-only apply 仍生成 verified backup；空数据库缺失目标表时 fail closed；Vector rollback 的 active restore 与 candidate/backup cleanup 同 transaction，cleanup failure 保留原 active candidate 并可重试；
- TaskPack whole-file rollback 在替换前校验 post-apply 逻辑 schema/data fingerprint，数据或后续迁移漂移时 fail closed，并把完整当前 operator provenance 注入临时 replacement；Vector/FTS switch、rollback handle 与 applied provenance 同 transaction 提交；owner lease 改由 backup 目录独立 sidecar 持有并按 token 释放，因此目标数据库 replace 期间仍保持串行化；
- fresh、partial、legacy、重复运行、并发/busy、WAL 与 Windows replace failure 由隔离 SQLite/index 动态测试覆盖。

本候选仍只表示 Migration Runner TaskPack 完成，不表示 Phase 3 完成。下一 TaskPack 必须执行跨 owner 集成验收。
