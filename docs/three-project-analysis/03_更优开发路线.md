# 更优开发路线

## 总原则

不要一开始做“大而全 OS”。
最佳路线是：

```text
先收敛
再打通
再扩展
再智能
再产品化
```

---

## Phase 0：三项目口径统一

目标：避免继续混乱。

任务：

```text
1. 建立总仓或总文档：Cognitive-Knowledge-System
2. 三项目分别写清楚 CURRENT_SCOPE
3. IR / KB / Cognitive-OS 的边界写死
4. 旧名、旧路线、旧规划全部 archive
5. 当前能跑的叫 active
6. 未闭环的叫 experimental
7. 未来想法叫 roadmap
```

输出：

```text
SYSTEM_MANIFEST.md
PROJECT_BOUNDARY.md
ASSET_REGISTRY.md
DATA_CONTRACT.md
ROADMAP.md
DECISIONS.md
```

---

## Phase 1：Knowledge-Base MVP 收敛

目标：先让 KB 真能用。

保留：

```text
documents
sources
chunks
FTS5 search
cards
reviews
mistakes
daily report
context pack
taskpack
trace
```

不做：

```text
完整知识宫殿
复杂学习画像
完整多 Agent
沙盒执行
自动联网执行
自动写长期记忆
```

验收：

```text
导入一份资料
→ 清洗
→ 入库
→ 可搜索
→ 生成卡片
→ 可复习
→ 可生成 Context Pack
→ 可生成 TaskPack
```

---

## Phase 2：Cognitive-OS 稳定成运行时

目标：所有执行都经过 Cognitive-OS。

要做：

```text
JSONL → SQLite
RoutePolicy
PermissionDecision
RunSession
ExecutionTrace
EvalResult
MachineLesson
Tool Registry v2
```

工具先只保留：

```text
file_read
safe_write
kb_search
context_pack.build
taskpack.generate
trace.write
```

`code_exec` 继续 blocked，直到沙盒和权限成熟。

---

## Phase 3：IR → KB 桥接

目标：研究能转工程资产。

流程：

```text
Research Note
→ Source Evidence
→ Intake Card
→ Engineering Contract
→ KB experimental
```

新增资产：

```text
intake_cards
engineering_contracts
adapter_candidates
open_source_profiles
license_risk_notes
```

新增 API：

```text
POST /ir/intake
POST /ir/contract
POST /kb/experimental/import
```

---

## Phase 4：A线最小学习闭环

目标：人真的能学。

最小闭环：

```text
Document
→ Card
→ Review
→ Mistake
→ Daily Report
→ Mastery Candidate
```

验收：

```text
导入一份资料
→ 生成卡片
→ 人审核
→ 复习三次
→ 出现掌握度变化
→ 错题能回流
```

---

## Phase 5：A→B 转译

目标：人学会之后，机器才能用。

触发条件：

```text
card.review_status = approved
review_count >= 3
mastery_score 达标
未解决 mistake = 0
source trust >= medium
publish_to_machine = true
```

输出：

```text
Canonical Summary
Machine Knowledge Unit
Conflict Detection Record
machine_candidate
machine_active
```

---

## Phase 6：B线 MCP / Agent 调用

目标：机器能安全调用。

MCP 工具收敛为：

```text
documents.search
documents.get
cards.due
context_pack.build
taskpack.generate
machine_knowledge.search
machine_knowledge.get
trace.write
```

暂不开放：

```text
delete
shell
git push
跨盘读写
自动执行代码
自动联网批量抓取
```

# 开发方法

## 契约驱动开发

每个模块先写：

```text
Schema
API
State Transition
Permission
Test
Fallback
```

再让 CODEX / DEEP 写代码。

## 标准任务包

```text
目标
输入
输出
涉及文件
禁止修改
数据结构
API
测试
验收
回滚
```

## Adapter 原则

```text
外部工具 → Adapter → 标准对象 → quarantine → review → core
```

禁止：

```text
外部工具 → 直接写核心数据库
```
