# 三项目边界与协作关系

## 一、不要合并成一个巨仓

三项目应该保持边界：

```text
Inspiration-Research = 研究与外部输入
Knowledge-Base       = 知识资产与学习/机器知识
Cognitive-OS         = 运行时与反馈
```

可以有总仓或总文档，但不建议把所有代码混在一起。

---

## 二、职责边界

### Inspiration-Research

负责：

```text
发现
调研
对比
验证
提出工程候选
生成 Intake Card
生成 Engineering Contract
```

不负责：

```text
长期知识管理
复习调度
任务执行
自动写机器记忆
```

### Knowledge-Base

负责：

```text
文档资产
搜索
卡片
复习
错题
学习报告
Context Pack
TaskPack
Machine Knowledge Unit
A→B 转译
```

不负责：

```text
直接执行高风险任务
直接联网抓取一切
无审核写长期机器记忆
```

### Cognitive-OS

负责：

```text
ingest
route
retrieve
compile_task
permission_check
execute
trace
evaluate
lesson
```

不负责：

```text
替代 KB
替代 IR
直接做完整学习系统
直接开放 shell / code_exec
```

---

## 三、协作关系

```text
IR 产出 Intake Card / Engineering Contract
        ↓
KB 接收为 experimental asset
        ↓
KB 人工或规则审核
        ↓
KB 生成学习资产 / 机器资产
        ↓
Cognitive-OS 接收 ContextPack / TaskPack
        ↓
Cognitive-OS 执行并生成 Trace / Eval / Lesson
        ↓
回流 KB / IR
```

---

## 四、关键数据合同

### IR → KB

```text
Research Note
Source Evidence
Intake Card
Engineering Contract
License Risk
Adapter Candidate
```

### KB → Cognitive-OS

```text
ContextPack
TaskPack
Tool Hint
Permission Scope
Risk Level
Success Criteria
```

### Cognitive-OS → KB / IR

```text
ExecutionTrace
EvalResult
MachineLesson
FailurePattern
NextConstraint
ResearchUpdate
```
