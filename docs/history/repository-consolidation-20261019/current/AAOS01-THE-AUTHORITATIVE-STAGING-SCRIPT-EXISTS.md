# 🎯 AAOS-01：**权威的分发脚本存在 —— 第 123 轮那个问题有答案了**

## 1. 找到了什么

```
scripts/release/stage_backend_runtime.py
  223:  help="site-packages the approved dependencies are copied from"
  283:  site_packages = root / "runtime" / "Lib" / "site-packages"
```

**项目**有**一个权威的 runtime 分发脚本** —— 它把**已批准的依赖从某个 site-packages **复制**进
`runtime/Lib/site-packages`。**

## 2. 这回答了第 123 轮我明确保留的那个问题

第 123 轮我观察到：安装器的文件表里**没有** `site-packages\app` / `archeaxis` / `shared`，
**但我没有据此下结论**，理由是：

> 「**这个工件的包内容来自**我的 staging**** —— 我 stage 的是裸 Python 发行版 + 用 **junction** 补的包；
> **junction 不会被 `tauri build` 打进安装器**；**正式发布流程可能另有准备步骤。**」

**现在那个「另有准备步骤」找到了** ✓ —— **就是 `stage_backend_runtime.py`**，**它复制真实文件**。

| 我当时的不确定 | 现在的答案 |
| --- | --- |
| 正式发布是否也缺包 | ❌ **不缺** —— 有脚本负责把包装进去 |
| 我的工件缺包说明什么 | **只说明我的 staging 是开发捷径** |

**所以第 123 轮那次克制是对的**：**我没有把「我的工件」说成「产品发布」。**

## 3. 它顺带解释了我踩过的那些坑

| 我遇到的 | 权威脚本本来会做的 |
| --- | --- |
| 构建产物里没有仓库包 | **脚本负责复制进去** |
| 我得手工建 junction 才能导入 | **脚本是正规做法** |
| 依赖要我一个个 pip 装 | **脚本从「已批准的」site-packages 复制** |

**即：我是用手工办法重现了 `stage_backend_runtime.py` 该做的事。**

## 4. 因此有一条**具体的、正规的**推进路径

```
用 scripts/release/stage_backend_runtime.py 正规地 stage runtime（真实文件，非 junction）
  -> tauri build 打包
     -> 安装器的文件表里应当出现仓库包
        -> 那样的产物才是有资格的安装候选（Q14 的前置）
```

**注意**：这仍然**不安装任何东西** —— 只是产出**正确内容**的工件。

**而真正的安装仍等你批准（决定 3）。**
