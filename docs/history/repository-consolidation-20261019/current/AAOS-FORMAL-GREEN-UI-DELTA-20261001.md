## Named controls and safe merge decision

XML inspection found **three Formal-only named controls** (the brand group above) and **four Green-only named controls** (the quick-capture status, mode label, text button and link button). Other named controls are shared. The Green-only controls depend on existing Green code-behind handlers; copying just the XAML into Formal or replacing the Green XAML with Formal would be unsafe. The Formal-only brand names would be a test-only transplant unless the visual hierarchy is intentionally changed. The existing Green shell already exposes the B10 brand and current responsive entry points. Accordingly, no additional high-impact UI-only patch is justified from this source delta alone.

Next review should compare native 720/840/1440 DIP windows in both themes and inspect the real Core quick-capture capability. Promote only a reviewed, bounded change. Keep Green user data, historic outputs and the dirty task tree untouched.

The 1280×900 Formal Home capture recorded at `docs/current/AAOS-VISUAL-QA-20261001.md` shows the lower graph below the first viewport and the node-details card below the fold. Its exact source is `.project-local/runs/be268a2d33/f5f5cc6b06db/artifacts/desktop-launch/2c083e046109472993d1fac1bec8dd09/home-core-final.png` (1600×1125 physical PNG at 125% scaling, SHA-256 `A2FC1FD23E5DAEF0B91132EF58C9EE9D3E741A4C6C0A03A35636028F3E03F33F`); the tested Desktop DLL was `8B46166F536BAFFCE3AC0E31B368B6AA722BCA84E856E114B50149470EC29275`. The graph itself is not clipped by its own bounds: `AaosMemoryGraphView` uses a 390 DIP canvas, with the lowest B10 node ending at approximately 361 DIP, and Home wraps it in a uniformly scaled Viewbox. The enclosing `WorkspaceScrollViewer` supports vertical scrolling. B10's `.split` becomes single-column only at **viewport width ≤1160px**; its graph stage has a **380px minimum height**. Shrinking the XAML Viewbox below that would reduce visual fidelity and leave the details card stacked.

The operative mismatch is in `MainWindow.axaml.cs`: `HomeGraphContentGrid` is switched to one column when **content width <1100 DIP**. At a 1280 DIP window the 280 DIP sidebar leaves about 1000 DIP of content, so the desktop graph/details pair stacks even though B10 remains two-column. At 720 DIP it should stack. Correcting this requires the code-behind responsive predicate (for example, a B10 viewport breakpoint), which belongs to the separate integration writer. No XAML-only patch or fabricated crop was made. Recheck both 1280×900 and 720×560 native captures after that predicate changes, including keyboard focus and vertical scroll reachability.
