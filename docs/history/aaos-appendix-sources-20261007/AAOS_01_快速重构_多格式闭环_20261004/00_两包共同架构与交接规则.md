# AAOS 两包共同架构与交接规则

版本：2026-10-04。第一包先完成快速重构与多格式真实闭环；第二包扩展长期能力。两份均采用 Tauri 2 + React/TypeScript/Vite、Rust Core、SQLite/CAS、隔离 Python worker。

用户“按照重构来”已经取代旧文件里继续纯 Avalonia、不新建 React/Tauri 的限制。实施者将其登记为现有 Authority 的可追溯 delta；不要把旧不可变任务包重写，也不要再问是否选择重构。重构不自动变成正式库覆盖、公开发布或替用户审批知识候选的授权。

正式业务写入由 Rust Core 执行；宿主、前端、worker、插件和 Agent 不直写 canonical DB。Core HTTP v2 与 NDJSON 优先复用。普通草稿保存和正式知识认可分开，来源和证据绑定版本。

本包表格是计划与验收规格，不是 production manifest，不预设 PASSED，不成为第二个 current truth。开工将任务映射到仓库现有 current 台账；方案中的 Q/F 编号用于本次交接，不替代仓库正式任务和 CAP ID。

第一包必须留给第二包：
- 完整 SHA/dirty、候选安装产物、Core 与 UI 身份。
- schema/合同/codec、数据副本和 CAS/备份身份。
- 真实格式矩阵、实际 worker 版本、可选依赖和未完成项。
- 已实现入口、完整有效能力目录和已测/未测状态。
- 迁移、恢复、退出、安装与源软件往返的具体证据。
- 精确下一项任务、写者归属、失败原因与恢复点。

已有仓库的 grant/issued-envelope 等机器规则按有效授权落实；现场缺工程登记时记录具体技术阻塞并继续不依赖它的准备任务，不伪造 grant，不把日常可逆实现全部变成新的人工审批。

不做强制清理、全局改环境/凭据、批量安装供体、自动大规模下载模型、双写旧新库或自动解冻 Release。不改 WORK-LAB/DESIGN-LAB 仓库；可选连接在各自独立任务中验证。
