# AAOS 未来延展与可持续架构任务包

版本：2026-10-04。对象：AAOS / ArcheAxis Knowledge。用途：以第一包的真实重构产物为基线，持续扩展全部有效未来能力。状态：架构与任务规格，供体已做资料核验，尚未完成 AAOS 接入验收。

主路线固定为 **Tauri 2 + React + TypeScript + Vite，Rust Core + SQLite/CAS，隔离能力 worker**。本包不再提出 Avalonia/Tauri 二选一，也不重新建设知识数据库。第一包交付真实可用产品；本包建设编辑、集合、互通、学习、科研、AI 资产、仿真、空间、协同和插件的长期能力。

可持续性通过四件事落实：数据属于 AAOS 的公开版本合同；供体通过可替换适配器接入；所有关键资产可离线导出和恢复；升级以行为回归和迁移演练验证。上游项目的宣传、Star、模型置信度和演示界面都不能代替这些证据。

## 1 基线与两包衔接

本包必须先读取第一包交接回执，确认实际客户端、Core、数据库、合同、能力矩阵和恢复版本。第一包没有通过的关键可靠性任务继续留在原队列，不能被未来模块的页面完成掩盖。

| 第一包交付 | 本包扩展 | 保持不变的边界 |
|---|---|---|
| Tauri 宿主与有限桥接 | Web/移动客户端、专用播放器 | 内容组件不直接绑定宿主 API |
| Document/Block、来源与锚点 | 集合、视图、公式、课程和场景 | 来源版本不可变，稳定对象 ID |
| 原件与 SQLite/CAS | 同步、共享、加密、长期归档 | 正式写入经 Core，索引可重建 |
| 格式 worker 与回执 | 更强解析、科研、仿真与训练 worker | worker 计算，Core 校验/提交 |
| 候选与学习事件 | 掌握诊断、AI 资产评测、协同变更 | 真人认可与机器候选分开 |
| 首个互通 profile | 全平台功能、往返、增量 | 独立源软件验证和损失登记 |
| 完整能力目录 | 产品插件、技能与提供方管理 | 规划、实现、连接与健康分开 |

2026-10-04 任务包和 CAPABILITY_ATLAS_V2 中的长期能力继续有效；Atlas 的状态及依赖有历史时点，必须与 current Authority 合并，不能把它的旧 supported 字样当作本轮安装版通过。

## 2 可持续技术架构

| 领域 | 默认实现 | 可替换边界 |
|---|---|---|
| 桌面 | Tauri 2 | HostAdapter：窗口、文件、通知、生命周期 |
| 交互界面 | React/TypeScript/Vite、一套 UI Tokens | 不将业务逻辑塞进主题或组件库 |
| 主编辑器 | Tiptap/ProseMirror | EditorAdapter 与版本化 Document codec |
| 原件阅读 | PDF.js + 格式专用阅读器 | ReaderAdapter、AnchorResolver |
| 数据视图 | TanStack Table/Virtual | CollectionQuery、ViewDefinition、FormulaEngine |
| 关系画布 | React Flow | GraphView 与空间布局，不替代关系真值 |
| 手绘白板 | Excalidraw 组件 | CanvasDocument、资产和知识引用映射 |
| 学习调度 | 先保留现有 py-fsrs；验证后可换 fsrs-rs | SchedulerAdapter、算法与参数版本 |
| 教学与课程 | DeepTutor/OpenMAIC 的选定模块 | TutorAdapter、CoursePackage 与 renderer |
| 科研问答 | Crossref/OpenAlex/Zotero/PaperQA2 适配 | ResearchJob、Source/Evidence 映射 |
| 3D | Three.js / React Three Fiber | SpatialPackage 与 RendererAdapter |
| XR | Godot/OpenXR 专用播放器候选 | 同一空间合同与能力握手 |
| 权威内核 | Rust 模块化单体 | 应用服务和存储接口，不绑窗口宿主 |
| 本地存储 | SQLite/CAS | StorePort；只有真实团队规模需要时再引入服务端存储 |
| 模型与工具 | 既有 ModelProvider + 官方 MCP SDK | 模型、能力和任务合同，预算由 Core 管 |

这些是方案选择。库提供基础交互或计算能力；AAOS 的版本、证据、语义、权限和恢复仍需实现。TanStack Table 不是 Notion 数据库引擎，React Flow 不是知识数据库，Yjs 不是批准系统，FSRS 不是掌握诊断。

避免“抽象所有可能未来实现”。接口围绕已确定的替换点建立；每个接口首先有一个真实实现和行为用例，第二个实现有明确收益时才加入。

## 3 统一领域模型

沿已有 Source/Knowledge/Evidence/Version 扩展以下对象：

| 对象族 | 长期必须表达 |
|---|---|
| 来源 | 原件、不可变版本、外部身份、抓取范围、许可与数据范围 |
| 文档 | 稳定块 ID、富文本/结构、未知节点、版本与编辑状态 |
| 知识与证据 | 主张、支持/反驳关系、具体锚点、审核与撤回 |
| 集合 | 类型化字段、记录、关系、汇总、筛选、排序、分组、视图 |
| 公式 | 原表达式、方言、依赖、类型、计算结果、引擎版本 |
| 人类学习 | 目标、先修、题目、误区、作答、评分依据、掌握证据、调度 |
| AI 资产 | 记忆、规则、技能、来源、适用范围、评测、认可与撤回 |
| 课程 | 场景、素材、交互、讲解、评分、学习事件、运行与降级要求 |
| 仿真 | 参数、单位、模型版本、执行边界、状态、可验证结果 |
| 空间 | 知识对象引用、坐标/单位、层级、场景版本、路线与资源 |
| 互通 | 外部 ID/版本、基准、字段映射、未知数据、损失、冲突 |
| 同步 | 修订、设备/主体、删除标记、日志序号、恢复与冲突 |
| 能力扩展 | 插件/技能/实现身份、权限、提供方、依赖、兼容版本 |
| 执行 | 输入快照、允许工具、预算、步骤、检查点、回执和结果 |

Document codec 保存引擎相关载荷与规范化对象之间的映射，未知字段与节点不静默删除。长期协同状态与正式来源/知识状态分开：协同草稿可变化，正式认可的知识和证据仍引用明确版本。

日期、单位、时区、公式与评分规则均按版本解释，不能用字符串同名掩盖语义差异。对象引用使用稳定 ID，文件名和标题是可变属性。为图谱、学习和空间生成投影时保留投影版本与重建入口。

不提前拆四套物理数据库。逻辑业务域通过类型、权限和生命周期区分。需要迁移 schema 时只在独立副本演练，以前向迁移和迁移前快照恢复为主要回退路线。

## 4 成熟技术复用原则

优先顺序：现有合格实现 → 上游公开组件/SDK → API/CLI 适配 → 选定模块 vendor/fork → 有明确缺口时自行实现。复刻成熟交互行为与信息组织，使用可合法复用的代码和资产；沿 AAOS 的品牌与领域模型实现。

每个供体必须登记精确 owner/repo、版本/commit、吸收范围、许可证/NOTICE、依赖、调用合同、资源峰值、回归样本、补丁、升级和退出路径。仓库级 MIT 不能代替包级核验。

| 能力 | 默认供体 | 集成方式 | 关键边界 |
|---|---|---|---|
| 富文本与块节点 | Tiptap/ProseMirror | 开源组件 + AAOS 领域节点 | Pro 扩展另有条款，不默认购买 |
| 文档与无限画布融合 | AFFiNE/BlockSuite | 替代主编辑器候选 | 不同时维护两套主编辑器；核验实际包的许可和嵌入接口 |
| PDF | PDF.js | 阅读组件 | 批注与证据进入 Core |
| 节点/流程/概念图 | React Flow | UI 组件 | 关系事实和布局分别保存 |
| 手绘 | Excalidraw | 编辑组件 | 托管服务的协作能力不自动包含 |
| 数据表格 | TanStack Table/Virtual | UI 组件 | 属性/关系/公式/视图语义由 Core 与合同实现 |
| 复杂文档 | Docling | 可选解析 worker | 代码 MIT；模型许可单独核验 |
| 间隔复习 | fsrs-rs | 经过对照的算法迁移候选 | BSD-3-Clause；不能直接继承既有调度参数而不验证 |
| 材料辅导 | HKUDS/DeepTutor | 选定能力/SDK/worker | Apache-2.0；不带入第二套持久记忆与通用 runtime |
| 课程结构和呈现 | THU-MAIC/OpenMAIC | DSL/renderer/导入导出模块 | root MIT；mathml2omml 等包保持独立许可 |
| 诊断策略 | ai-for-edu/LearningMAP | 方法/选定模块 | Apache-2.0；先评测适配学科和材料 |
| 自适应学习交互 | zijinz456/OpenTutor | 参考/选定组件 | MIT；项目自述不算 AAOS 生产验收 |
| 文献问答 | Future-House/paper-qa | 研究 worker | Apache-2.0；生成引用必须回到 AAOS 来源 |
| 协同草稿 | Yjs | 后续内容协同组件 | CRDT 不替代授权、业务冲突或真人认可 |
| 数学动画 | ManimCommunity/manim | 渲染 worker | MIT；生成视频和交互仿真分别验收 |
| 3D | Three.js/R3F | 场景组件 | 3D 显示不代表 XR 设备支持 |
| XR | Godot/OpenXR | 可选独立播放器 | 单独设备、输入与发行验证 |
| 对外工具 | 官方 MCP Rust SDK | 受限领域接口 | 工具协议不自带业务授权 |

Tiptap 的开源核心与收费扩展边界见官方文档。[S06] AFFiNE 的不同目录存在不同许可范围，不能把整个仓库按一个宽松许可吸收。[S11] Docling 明确把代码许可与模型许可分开。[S12] OpenMAIC README 列出课程 DSL、渲染和持久化模块，同时注明 mathml2omml 的 LGPL-3.0-or-later 条款；优先抽取需要的模块。[S13]

tldraw 生产使用需要有效许可，不作为默认无许可基础。[S14] 不为了供体名称而自动部署 Docker、Next.js/PostgreSQL 或另一套账户系统。若抽取成本太高，先作为可选外部服务产物适配；不得因此暗中增加正式默认运行时。

## 5 编辑器与复杂内容

Tiptap/ProseMirror 是本包默认主编辑器。依次完成块拖拽、嵌套、引用、公式、代码、表格、附件、模板、评论和领域节点；每种节点有稳定 ID、版本、导入导出与未知节点行为。

如果未来“文档与无限画布共用同一块模型并无缝切换”成为主工作区的硬门槛，且 BlockSuite 的真实嵌入、IME、持久化、资源、许可证和迁移用例全部通过，可在 EditorAdapter 下替换主编辑器。替换时用相同文档集比较，不把两套编辑引擎同时作为默认。

复用原则：沿用上游节点与插件体系；AAOS 自建的是证据节点、学习节点、知识引用和 Core codec。中文输入法、跨应用粘贴、撤销、大文档、焦点、无障碍和离线导出是每次升级的保留回归样本。

规范化内容、引擎载荷和派生检索绑定同一 revision，不能编辑一个 JSON 而让数据库视图保留另一份文本。未来协同使用 Yjs 时，草稿操作保存/同步与正式提交的校验分开，拒绝“收到 CRDT update 即自动认可知识”。

## 6 数据库视图和知识图谱

先实现 Collection/Property/Record/Relation/View 的领域合同，再用 TanStack 做表格交互。逐步增加列表、看板、日历、画廊、筛选/排序/分组、双向关系、汇总和公式。

公式采用有类型的 AST 或受限解释器，设置运算/深度/时间预算；不执行导入字符串中的 JavaScript 或 Shell。不同源平台的公式方言由 adapter 处理，保留原表达式、计算值与缺口，不用相似结果冒充语义等价。

搜索先保持 FTS5 独立可用。中文要明确分词/检索策略和版本，不能假定默认英文 tokenizer 就能满足中文任务。向量索引保存 embedding 模型、分块、维度、版本和源内容哈希；更换模型后重建，不能混用向量。只有真实检索收益和容量证据需要时再增加重型索引服务。

图谱事实存储为可追溯对象和关系；React Flow/其他图组件负责视图，位置是单独布局版本。派生关联标明推断，不混同已认可关系。大图按问题和范围加载，不一次渲染全部历史节点。

继续保留最新任务包的完整目标：功能等价、数据兼容、双向往返、连续增量互操作四项独立验收。第一包的 Markdown/Obsidian profile 只是起点。

| 批次 | 范围 | 重点 |
|---|---|---|
| I1 | Markdown、Obsidian、JSON Canvas | 链接、块 ID、属性、资源、画布对象与两方向回读 |
| I2 | Notion、思源、Joplin、Logseq | 块/属性/关系、视图、公式、元数据与源侧限制 |
| I3 | Zotero、Anki | 文献、批注、引用键、卡片模板、历史、调度与媒体 |
| I4 | AFFiNE、AppFlowy、Outline、Docmost、Wiki.js、BookStack、Anytype、Trilium | 内容/视图/协作/权限/历史的具体 profile |
| I5 | Evernote、OneNote、语雀、飞书、Confluence 及其他有效个人知识工具 | 实际格式/API 与账号授权、可获取范围 |
| I6 | RAGFlow、FastGPT、MaxKB、Dify、WeKnora、Git 与研发资料 | 语料、切块、配置、引用和评测；向量可重建 |
| 持续发现 | Apple Notes、Bear、Craft、Heptabase、Tana、Capacities、RemNote、Roam 等 | 有实际需求提高优先级，其他有效需求保持可见 |

平台 × 版本 × 功能 × 方向 × 样本形成资格化记录，继续沿用六类状态：
VERIFIED_LOSSLESS_PROFILE、FUNCTIONAL_EQUIVALENT、ROUNDTRIP_PRESERVED_ONLY、PARTIAL_WITH_LOSS、BLOCKED_EXTERNAL、UNVERIFIED。

完整流程：外部创建 → 导入 AAOS → AAOS 修改 → 回写外部测试空间 → 外部软件打开验证 → 外部再改 → 增量导回 AAOS。反方向 AAOS 创建也需独立验证。源平台没有开放的权限、历史或视图等信息记作缺口；未知字段保留只能证明保全，不证明 AAOS 已能操作该功能。

同步用基准版本与三方差异处理冲突。删除使用 tombstone 和策略，不把本次分页没读到当删除；恢复只撤回本次任务的更改，不能抹掉用户之后的编辑。

Notion 官方明确导出后重传不能立即重建整个工作区，因此必须组合文件、API 和功能映射验收。[S15] Anki collection package 的回导可能替换整库，所有往返测试在隔离 profile；调度记录与模板/媒体单独核验。[S16] JSON Canvas 有对象化节点和边，应以结构而非截图适配。[S17]

## 8 人类学习与 AI 学习

人类学习形成：来源和目标 → 知识点/先修 → 诊断 → 辅导/课程 → 作答与讲解 → 掌握证据 → 复习 → 迁移应用。

DeepTutor 优先提供基于材料的辅导、练习与研究模块；LearningMAP 提供诊断/知识点策略候选；OpenTutor 提供补充交互参考。三者先比较能填补的具体缺口、成本和效果，不叠加三套 tutor 服务。[S18][S19][S20]

FSRS 只负责复习调度。掌握诊断要有版本化准则、客观题、讲解质量、迁移题、误区和多次证据。阅读次数、自评和模型置信度不能当作客观掌握。保留 unassessed、insufficient_evidence 等含义，不虚构漂亮掌握率。

AI 学习资产形成：成功/失败/纠正 → 候选 Memory/Rule/Skill → 来源绑定 → 评测 → 人类认可 → 有范围使用 → 使用回执 → 退化检测与撤回。资产的可用性、来源可信度和评测效果分别展示。

参数训练单独作为可选实验链：有许可的数据集版本 → 模型/训练配置 → 资源检查 → 训练 → 独立评测 → 资产批准 → 回滚。8GB 显存机器不承担所有大型训练任务；基础产品不依赖训练成功。模型目录和服务优先共用现有有效入口，变更模型不改变知识真值。

## 9 课程与视觉教学

建立可离线恢复的 CoursePackage，包含版本、学习目标、知识引用、场景、素材、讲解、题目/评分、学习事件、运行依赖和降级行为。采用 OpenMAIC 的选定 DSL/renderer/交换模块为供体，并映射到 AAOS 的来源、对象和事件。[S13]

默认用 AAOS Core 保存课程与学习进度，不为课件默认增加 OpenMAIC 的独立 Next.js/PostgreSQL 服务。抽取模块前先验证实际依赖；若确有不可拆依赖，作为明确可选的独立供体服务或采用导出包适配，不能将其自动列入基础产品。

课程资源全部记录与离线打包。HTML 是一种渲染结果，不是课程唯一真值。缺媒体、插件或 3D 能力时，有文本/静态帧/2D 降级；关闭播放器再打开可继续。

模板式教学交互优先于任意生成代码。动态生成 HTML/JS 在无桌面权限的独立隔离环境运行，限制通信、网络与资产，并返回结构化学习事件；禁止把课程脚本放进主 Tauri 窗口后开放 IPC。

## 10 动画与仿真

Manim 用于数学/解释动画 worker，结果是可回放资产。[S21] 交互仿真则由参数模型、计算引擎、交互组件和实验记录组成；视频不能代替可调参数反馈。

先实现一到两个可核验模板，例如概率、运动或电路，再扩展学科。每个仿真记录参数、单位、算法版本、初始条件、结果、数值误差边界和引用。纯浏览器小型计算可在受限计算 worker；复杂科学计算放 Python/WASM/其他已核验引擎。具体引擎按实际学科选择，不为“仿真平台”预装所有软件。

生成代码必须先按受限模板或操作系统隔离执行，NDJSON 只是通信协议。设置文件、网络、进程、CPU/GPU、时间和输出预算，异常结果不会自动进入可信知识。

## 11 空间记忆与 XR

SpatialPackage 以知识对象 ID 为核心，保存 World/Room/Locus/Route、坐标与单位、布局版本、资源与许可、交互和学习事件。同一知识对象可对应多个布局。

路径为：2D 记忆地图 → CSS/Canvas 2.5D → Three.js/R3F 桌面 3D → 专用 Godot/OpenXR 播放器 → 按具体设备设计 AR。2D/文本始终是可用降级，不要求一开始携带整个 3D 引擎。[S22][S23]

3D 显示、VR 设备连接、交互输入、定位、AR 相机和移动发行分别验收。不能因为 Tauri WebView 能显示场景，就承诺所有头显可用。XR 播放器与 Core 使用有限协议和同一场景版本，设备断开后不会丢学习记录。

空间界面的价值用具体学习任务评测：路线记忆、知识定位、迁移应用及认知负荷。视觉精美与学习有效性分别记录。保留资产包迁出能力；glTF 等开放资源格式作为优先交换候选，场景语义不绑定某一个游戏引擎。

## 12 研究与项目空间

第一批沿第一包的 Source/Evidence 管线接 Crossref/OpenAlex 的元数据检索，并适配 Zotero 文献与附件。区分元数据、摘要、可获取全文与用户已授权文献，不以检索到标题冒充已导入原文。[S24][S25][S26]

PaperQA2 作为研究 worker 候选，文献和结论必须映射回 AAOS 来源版本、锚点和候选审核。保留问题、检索范围、方法、相互独立的来源、反证和不确定项。[S27]

课程、科研与研发项目使用统一 Project/Artifact/Experiment/Rubric 合同。模型输出先成为候选，科研验证记录输入、环境、方法和可重现产物。不自动下载并执行论文仓库中的任意代码。

研究平台和开源吸收池通过同一 Provider/Donor 登记管理；引用接入、代码吸收与本次实际调用分别显示。没有现成真实项目需求的 API 保持候选，不无限增加平台和账号。

## 13 协同 同步 移动与安全

本地单人保持完整离线能力。随后按真实需求增加设备同步，再增加多人协作；同步文件与同步业务对象是不同问题。

Yjs 适合可变文档草稿协同；业务权限、公式、删除、知识认可、审计和迁移冲突仍经 Core。[S28] 同步协议包含对象/版本、tombstone、资产哈希、能力版本、checkpoint、重试与授权撤销。同步服务器不是第二知识解释系统。

SQLite 权威库保留本地能力。真的需要多人服务器时，可通过 StorePort/应用服务评估 PostgreSQL 或其他成熟服务端组件，但必须证明查询、权限、备份与迁移收益；不作为第一包前置条件。

移动/Web 先提供阅读、搜索、复习和捕获；通过已认证服务接口或离线缓存适配 Core，不假设手机可以直接访问 Windows 的 127.0.0.1，也不把整套 Python worker 塞进移动端。后续根据设备和任务选择 PWA 或 Tauri 移动宿主。

凭据使用操作系统安全存储和引用，不进入课程或普通备份。加密将本地数据库/资产、传输、同步端和密钥恢复分别设计。加密后全文/向量搜索的能力与威胁模型要说明；禁止自行发明密码算法。具体加密依赖经许可和恢复验收后选择。

## 14 插件 技能和受控 Agent

一个能力有一个稳定 capability_id，可由不同 Implementation 提供。Catalog、RuntimeManifest、Connection、Health/Receipt、CompatibilityProfile 分别有单一来源。产品插件、技能、worker、提供方不能使用同一个 ID 混成一种对象。

插件分三类：可信 UI 组件、独立能力 worker、外部 Provider/Tool。第一批可采用安装前核验的 manifest + 明确目录 + 可禁用生命周期；不必先造一个 Marketplace。第三方不可信 UI/代码默认不拿主窗口权限。

Manifest 包含依赖、版本范围、输入/输出 schema、网络/文件/预算权限、提供能力、资产、健康探测、升级与退出。权限来自 Core 策略，不由插件自己声明后自动放行。未来 WASM/WIT 可以作为特定计算插件候选，接口先预留语义边界，不提前实现复杂通用沙箱。

知识 Agent 只协调资料学习、研究对比和研发资料包等有限任务。它调用已经接通的能力，使用持久 Job、步骤、预算、取消、检查点和回执，不重建通用 Agent OS。复杂上游工作流作为 worker 候选吸收，最终写入仍在 Core。

用官方 MCP Rust SDK 暴露 search/context/propose/task/status 等受限工具；读权限不自动允许正式修改，human approval 不接受 agent 自传字符串。[S29] WORK-LAB 可选协调通用执行，DESIGN-LAB 可选提供设计产物，AAOS 独立安装仍能使用。

## 16 维护与退出路径

- 锁定依赖、工具链与精确供体 revision；升级先在独立分支与数据副本演练，合并前跑保留旅程。
- 每个自有模块有一个 owner、公开合同与少量关键行为测试；不用庞大治理文档代替可运行交付。
- 供体补丁保持小且有目的。补丁越来越多时评估贡献上游、替换供体或缩小吸收范围，避免维护整套深 fork。
- 缓存、FTS、向量和图视图都能重建；用户数据、来源、证据、课程和学习记录可结构化导出。
- 备份与恢复包含 CAS 引用与 schema 身份；定期恢复到独立副本验证，不依赖上游在线服务。
- 学习效果、模型效果、兼容性、性能和视觉分别验收。一个平台版本升级使 profile 失效时显示需重验，不沿用旧绿灯。
- 第一包的性能、许可、网络与预算边界继续有效。离线资源懒加载，重型 GPU 工作排队，新增引擎先记录峰值。
- 不固定虚构工期、人日或“85% 完成”。以真实切片与回执推进，所有 NOT_RUN/BLOCKED 项继续可见。
