# 执行顺序、任务依赖与多人协作

## 1. 推荐分工

DSH：Core/worker/启动/契约与迁移写入一致性。Codex：Avalonia 壳、全部能力导航、页面、控件、UI 状态和视觉。Hermes：只读对账、限定外部资料核验、测试编排与集成回执。

分工不锁模型、不要求新增付费订阅；现场已有 owner 优先。同一文件 single writer，共享 DTO、manifest、schema 或状态台账由一个明确 owner 修改，其他人提供变更请求。多 Agent 可以并行读/审，不同时改同一数据库或工作树。

## 2. 阶段与可并行部分

| 阶段 | 主要交付 | 依赖/并行关系 | 退出条件 |
|---|---|---|---|
| E0 现场与范围 | 真实仓库、authority、writer、现有能力和兼容差距 | 起点；先只读，按需取历史索引 | G0；本轮新增全能力兼容要求有 delta 登记 |
| E1 工程+视觉样板 | 单源分发、启动/事务/捕获可靠；阅读证据样板 | DSH 与 Codex 按文件并行，DTO 先约定 | 必需 worker 最终包可调用；样板可评审 |
| E2 全目录与能力中心 | 所有有效能力路径、未来详情、平台/技能/调用状态 | 不依赖所有后台完成 | 导航无遗漏/死链；无假可用状态 |
| E3 当前闭环+UI 扩展 | 真实候选、学习/纠错、冷启动恢复；资料库等页面统一 | 原生视觉不拖到全部后端后；真人 Gate 单独 | G1/G2/G4 的本切片通过 |
| E4a 科研 API | Crossref/OpenAlex 真实资料入口 | G0 后可隔离设计；实现按扩展合同，不塞 M0 | API profile 的 G3 |
| E4b 知识库兼容 K0–K5 | 全功能矩阵、交换合同、逐库迁入迁出与往返 | K0 与 E0/E2 同步；K1 优先，K2–K5 连续后续任务 | 每个 profile 独立证书与缺口，未到全量不得全称完成 |
| E4c 学习供体 | 用既有能力+必要供体跑通学习体验 | 来源/学习写入稳定后，和 API 读适配可分文件并行 | 真实输入、反馈、事件、重启证据 |
| E5 专用 Agent | 三种有界技能与恢复/审批/预算 | 只调用已验收工具，不等所有未来能力实现 | 任务产物可核验，失败/取消不假成功 |
| E6 集成交付 | 最新分支合并候选、完整回归、Owner 决策 | 可对每个稳定切片循环执行 | PR、部署、发布门禁分别明确 |

E4a/b/c 是并列交付流，不要求等待“所有知识库全能力”才接第一个 API；也不能因 API 先完成就取消兼容流。长期 capability parity 保持在任务注册表与界面中。

## 3. 首批工作项

机器可读的 `registries/tasks.json` 给出任务、owner、依赖、验收、审批和初始待执行状态。任务号是本包 W 编号，映射到现有工作单元，不覆盖 R6/Axx 或仓库已有编号。

先做 W00–W03（只读确认与范围），随后 W04–W09（可靠性）与 W10–W12（样板/目录）并行；W13–W18 完成现有闭环与视觉。W19–W24 进入领域与兼容首批，W25 后按已满足依赖推进。具体顺序以 JSON 依赖图为准。

## 4. 现场命令原则

只读身份检查可使用现有 git，不触发安装：

```text
git rev-parse --show-toplevel
git rev-parse HEAD
git status --short
git worktree list --porcelain
git branch --show-current
git remote -v
```

输出中的含凭据 URL 必须脱敏。`git fetch` 会更新本地 refs，按已有许可执行；禁止 force、reset、clean 或覆盖工作树。测试命令从当前 repo 的 AGENTS/CI/脚本读取，不猜 cargo package 或 .NET 项目路径，不自造数据库路径。

## 5. 状态更新与中断恢复

每个工作单元最多一个活动 writer，结束给短回执并更新现有可变台账。中断时记录已改文件、未完成测试、启动进程、是否存在临时写入和下一动作；下一会话先读取回执与任务章节，不重新审计所有历史。

遇到 Owner Gate、密钥、缺文档或环境，不把任务伪装通过。记录最小阻塞及安全默认，继续独立项；不要为了继续自动降级审批、换正式框架或付费。

## 6. 防止再次只交文档

E0 对账只需产出足以定位任务的最小回执，不再写几十页历史报告。每个开发单元的成果必须包含实际代码/测试或明确阻塞；UI 单元必须有运行窗口；迁移单元必须有导入导出/回读证据。

本包是用户要求的交接材料，不是要求执行器再生成一套同名大蓝图。包内 registries 是需求种子/计划，不作为第二完成台账，应用到仓库时映射并沿原 authority 管理。
