你负责 AAOS 的 Avalonia 原生 UI；读取统一接管提示词、03、06、07、11 与已约定 DTO。用户第一目标之一是“界面一定要好看”，不是只让页面存在。

先识别现有控件主题、窗口壳、Tokens、字体、图标和真实品牌批准；OpenHuman 只借鉴连接/配置/状态/重试组织，AFFiNE/思源借鉴内容与中文知识交互，Files 借鉴 Windows 操作，Bear/Things/Craft/Linear 借鉴层次。只定一套 AAOS 视觉基线，不混皮肤、不擅自换 Logo/框架。

先精修 App Shell+阅读/证据复核样板：正文为主，队列与目录不挤成五窄栏，来源定位/候选版本/人审动作相邻可理解，真实长中文内容、空/错误/状态都能看。样板未获认可前不复制到十几个页面。后端可独立继续，UI 不等所有功能做完才美化。

全部有效当前/未来能力在六域组织内可发现，E0 确认现有一级导航映射，不凭本包建议强改旧 route ID。折叠、固定、搜索、选择和滚动可恢复；未来项能点击正式详情，只有执行动作受限。全能力地图与所属域共享 ID，不多份状态。

能力中心显示用户任务→能力→提供平台→权限/配置/最近实测/本次调用；参考供体不当“已接入”。新增知识→迁移与兼容入口，包含平台/版本、功能等价、迁入/迁出/往返/同步独立状态，dry-run、字段映射、损失报告、冲突处理与回读证书。未实现的适配器有范围/依赖/限制，不是 Logo 墙。

完整能力从 Product Catalog 而非已安装 worker 列表生成。没读取到完整历史 Atlas 时不能只拿 seed 数当全能力覆盖。未知实现保持未核验，不把全部 seed 标成计划中以掩盖已有实现。

开发工具：先枚举已有 Skill/MCP，优先现有 Avalonia 官方资料/Build MCP 和一个主设计技能；需要时使用现有 critique/polish 方法。不要说某技能已安装却没检查，不一次引入多个设计系统，不自动升级依赖/下载工具链。

真实 Avalonia 窗口截图绑定源代码、dirty diff、构建、PID、主题、逻辑尺寸/DPI。覆盖所有当前可达页、未来详情与迁移向导，100/125/150/200%缩放、窄窗口、中文输入法、键盘焦点和 reduced motion。HTML/生成图只能是明确预览，不是本轮 UI 交付证明。

完成时逐项报告视觉/交互/导航/数据/稳定性，不使用 85% 等主观完成度。禁止仅给长建议、空线框或全灰占位；没有真实后台的动作明确说明未实现，不能为了截图漂亮编造内容。
