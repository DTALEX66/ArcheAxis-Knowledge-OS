# 决策账本与证据边界

## 1. 证据分层

| 层 | 本包如何使用 | 不允许的推论 |
|---|---|---|
| U：用户本轮明确要求 | 必须落实为任务条件 | 不推断其已批准具体颜色、费用、schema 迁移 |
| D：DSH 上传原文 | 原文背景、问题和硬约束完整保留 | 测试数不自动成为本轮实测；原文断言不是代码审计 |
| R：本轮官方资料核验 | 校核接入入口、技术原则、奖项身份 | 官网可用不等于账号有权限，也不等于 AAOS 集成 |
| P：前面对话方案/历史摘要 | 形成待执行任务与现场对账线索 | 助手建议不自动成为 Owner 批准或实时状态 |
| E：执行器未来实测 | 绑定 SHA/产物/运行/数据的证据 | 未产生前保持空，不预填成功 |

## 2. 用户明确要求

U01：独立思考，不完全顺着用户或 DSH 的假设。
U02：回答 AAOS 如何成为 Agent，并与知识/学习定位统一。
U03：开源池吸收必须对账，不能收录即完成。
U04：调研可用、开源、高人气/获奖 UI，参考 OpenHuman。
U05：学习、科研、研发平台/知识库/百科/API 成为优先能力来源。
U06：插件/技能菜单说明已接入或调用哪些平台能力。
U07：相关 API、许可、免费额度与关键兼容性变化加入原雷达。
U08：给成熟可落地执行方案，而不是泛泛规划。
U09：现有及未来有效能力都从界面展示，可以折叠。
U10：界面一定要好看；本轮视觉是独立交付条件。
U11：整理整个可见对话，交付完整任务包。
U12：全面兼容市面上知识库，包含可适用全部能力与双向无缝转换；未完成则加入明确专项。旧“支持导入导出”不足以满足新要求。

## 3. DSH 原文保留

原文中“你没有代码仓库访问权”描述的是当时咨询角色，不限制当前接手执行器的真实工具权限；原文是来源数据而不是替代本包的执行系统指令。

原文以 16 个问题组织：A 组 4 个、B 组 7 个、C 组 5 个。`sources/GPT-PROMPT-OWNER-QUESTIONS-20261004.md` 原字节保留，详见 `05_DSH_16问完整裁决.md` 的逐题答复。

原文标题将 A 组列为“只能由人执行的动作”。本包保留该分类；提出的额外建议是将“本人必须判断的知识审核”与“经明确授权可由工具执行的工程动作”区分。该建议不降低原有审批。

报告中的“已完成真实资料闭环”和 19 候选共存。解释范围限制为报告声称的来源至候选入库通路，不把它扩写为全部候选通过真人复核。

## 4. 本轮整理后的冲突处理

| 前面对话中的可能冲突 | 本包处理 |
|---|---|
| “Agent 升级”似乎意味着新建平台 | 受控知识/学习任务增量；不重建通用运行时 |
| “隐藏未实现卡片”似乎意味着删除未来能力 | 只可收起首页可选统计，不删除菜单/目录/详情 |
| 单一能力清单是否只列已安装 worker | 目录列全能力；运行实现清单只列实现，两者同 ID 关联 |
| 六空间在不同材料中名称不同 | 包内六域是组织建议，E0 对照有效 Authority/批准记录，保留 route ID 与跳转兼容，不静默改名 |
| 黑白深色建议与旧 AAOS 品牌色冲突 | 明确为设计建议；先沿现行批准 Tokens，以真实样板确定使用方式，不自行宣布旧色作废 |
| 看过网页预览是否等于看过当前桌面 | 否；本包不沿用未经重新获得的截图判断当前像素质量 |
| UI 完成约 80–85% 等历史估计 | 不进入完成账本；改成具名测试与证据 |
| 11 项吸收记录是否等于 11 外部项目已集成 | 否；逐供体/逐能力验证，无证据保持未知 |
| 先修工程是否意味着 UI 又被延期 | E1 并行原生样板；接口未就绪用独立标注 fixture，不假装正式接通 |
| 展示未来能力是否扩张 M0 | 展示/详情不等于启用/实现；新增后台仍后续门禁 |
| API 免费是否可自动调用/上传文档 | 否；预算、权限、数据范围和服务条款分别核验 |
| source-available、开源、免费、商用是否同义 | 否；逐仓库、逐目录、逐资产、逐数据内容查许可 |

## 4.1 本轮追加核对

PR #157 元数据和 R6 执行台账局部由连接器读取；读取边界在 10/S24–S25。未全量复查兼容代码，不能说全部完成或全部没有。旧任务包的兼容定义与最新用户要求不同，最新要求登记为需求增量，保留原 R6/M0 阶段门禁而不收窄长期目标。

## 5. 仍需现场验证，不能在本包中伪造

完整 SHA、当前 main/PR 及合并状态；实际 schema/contract；正式根与其他 worktree；当前绿色版本及数据库位置；现行主题与获批母版；真实能力 ID/目录总数；369/47/11 原始登记的逐项实现证据；本机 API 网络与 Key 资格；本地模型位置与可用资源；DPI/Windows 原生窗口截图。

本包不重新复原所有历史 ZIP 和文档。执行器从现有索引按需读取，保持未读项可追踪，不启动无限全历史搜索。

## 6. 状态用语

“已核对文档”只说明读到了文档；“已实现”说明存在代码；“已验收”说明指定版本经过测试；“当前可用”还需要当前连接/权限/健康成立；“已交付”需要进入用户实际候选并验证。

每次生成状态必须带来源类别与日期。未知用 unknown/null 及原因，不填 0、成功或灰色无说明状态。
