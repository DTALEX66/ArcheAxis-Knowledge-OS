AAOS UI 成熟落地深化方案

当前目标是让用户容易开始、持续工作并恢复现场，让开发者明确每个入口实际读取什么、修改什么和怎样判断完成。现有深空蓝与冰蓝体系可以继续使用；下一层深化集中在导航、任务连续性和真实操作。

一 导航与对象结构

日常一级导航：工作台、知识、学习、AI、资源。固定工具：全部能力、设置。全局搜索在顶栏，空间/项目范围在同一处显示；默认复用现有个人空间与项目模型。研究空间归知识工作区，允许收藏到快捷区。收藏和最近访问只改变入口便利性，不复制业务对象或资格状态。

工作台：继续上次现场、待复习、最近知识、真实待处理项。知识：集合/内容列表、阅读编辑、反链图谱、研究空间。学习：学习目标、路径、课程、练习、复习巩固、学习记录与画像；课程准备是其中一条上下文旅程。AI：项目记忆、知识包/规则技能、经验候选、纠正复测和有限任务回执。资源：模板/插件/供体、导入导出和互通。全部能力：完整能力目录与细项详情。设置：模型预算、权限数据、备份恢复、同步和客户端能力。

22页继续作为可深链接视图和工作步骤，逐页映射见02。教学需求、表达方案、交付、反馈不再占据常驻一级导航；课程内有明确入口和阶段记录。直接进入阶段视图时仍显示课程/教学项目上下文和返回目标。版本、来源、历史通过对象详情进入，也在设置中保留全局查询。关键能力保留普通用户可达的固定入口与全局检索；未来能力可阅读详情、查看依赖与未完成状态，不能做成无法点击的灰卡。

旧路由、快捷键、深链接、草稿恢复、筛选和独有行为先逐项映射。新导航合并页面职责前先核对当前组件。旧地址优先重定向到同一对象的新位置；没有迁移证据时保留旧入口及说明。菜单收敛不能成为删能力或批量归档代码的理由。

二 全局界面与视觉规则

顶栏承接当前位置、全局搜索、新建菜单和轻量运行提示。新建明确区分笔记、导入原件、学习目标等实际可用对象；新建项由已验证的现有能力提供，避免一个模糊按钮永远跳到编辑演示页。新建笔记允许立即输入，依据、课程采用和AI资格均不是保存前置条件。

品牌名称与正式图形使用用户有效素材，不新造Logo或擅自改名。宇宙质感用于欢迎页、封面、课程视觉与空态插画；编辑正文和数据列表使用安静纯色。工作台首次欢迎可用大封面，日常横幅建议收至80—120 CSS px且可收起。继续上次工作优先出现在首屏。无数据时提供真实新建/导入入口，不展示虚构学习进度、掌握评分或AI收益。

建议视觉参数是可评审的目标值：导航正文14px，业务正文14—16px，持续阅读16px起并允许调整，辅助说明12—13px，技术ID使用辅助等宽样式。长正文行高建议1.75—1.95，阅读文本宽度约640—760 CSS px。主操作36—40px高；触屏适配另核对触达大小。大字号/缩放不得被固定卡片高度截断。

深浅色使用统一语义tokens；组件不能把原深色十六进制直接写死。主题变化只更新主题变量与偏好，不改变业务对象、编辑会话、选择范围或路由。未来重出图锁定相同视口、真实字重、字体fallback、内容长度和主题。图片切片用于装饰/参考，正文、按钮、状态和表格由组件呈现。

每个任务区域只有一个显著主动作，其余为次级或菜单项。卡片只用于对象概览与入口；编辑、练习、比较版本、导入和恢复分别采用适合任务的布局。状态用文字和必要图标表达；颜色可辅助，不独立承载保存/权限等含义。对比度、键盘、屏幕阅读和焦点行为必须实际检查，截图观感不能证明通过。

三 工作台与知识工作区

工作台先显示可恢复的真实对象，保留滚动位置和筛选上下文；其次给出到期复习、最近笔记与导入进展。没有学习目标时显示可开始的目标入口；没有AI活动时不占一整块空白仪表盘。待办可折叠或个性化，不能变成单一健康分数。

知识工作区由集合导航、内容列表和可选详情组成。选择集合只改变视图，原对象ID与来源身份不变。列表优先显示标题、内容类型、修改时间和当前相关状态；依据、采用、AI资格等多维信息在详情中分组。多格式原件可先保存，解析失败保留原件与损失回执。研究空间保留问题、假设、原文、反证、方法、实验和未决，不能因收起导航而缩成只有笔记列表。

全局搜索默认搜索现有可用知识/课程与能力目录，显示对象类型、范围和来源。索引不可用时给出降级与原因；可用的本地搜索不应被远程AI失效阻断。语义搜索的可用性、模型与结果来源单独说明。搜索结果用真实对象链接，未来能力结果进入说明页；键盘可聚焦、选择、打开、返回原现场。不能把原型标题匹配当成业务全文检索已接入。

四 阅读与编辑

对象身份、标题、保存状态和必要的版本提示构成轻量顶栏。正文是主区域；来源、属性、反链、资格和历史通过可折叠Inspector访问。默认展示当前任务所需的信息。例如原件阅读显示来源，原创草稿强调保存；识别忠实度只在相关对象适用时显示。未知、未评估、不适用分开，不能统一绿色。

阅读、编辑、原件、版本比较具有清晰边界。采用现有成熟编辑器和文档模型，持续承接选区、撤销重做、粘贴、中文输入、块/页面链接及历史锚点。普通草稿允许随时写，来源/依据之后补充。查看原件和历史版本默认只读，修订操作从明确入口创建新版本。课程仍绑定原知识版本；新内容不得静默替换引用。

草稿的归属至少能定位当前真实对象或临时对象、编辑会话与基于的版本；具体结构复用现有Core契约。禁止所有文档共用一个localStorage键，禁止把演示HTML当生产模型保存。theme/render/page-key的改变不能重建未保存正文。中文composition过程中保留输入，持久化提交顺序由成熟编辑器与当前保存管线承接。每次写入回执匹配对象与版本，迟到回执不能将更新的编辑误标已保存。

保存提示至少分清本地编辑、正在提交、Core确认持久化、失败/待重试和版本冲突。只有收到真实持久化回执才显示已保存；离线保存成立取决于该环境是否有实际可用的持久化能力。远程同步状态另列，不应遮盖本地保存成功。权限变化阻止不合法提交，同时保留草稿供复制/按当前授权另存。失败与冲突不得静默清空编辑内容。

导航离开、窗口关闭、主题切换、快速切文档、重启回读分别验收。优先让已持久草稿自动恢复；确有未落盘风险时明确给出留在页面、重试或导出草稿等可用动作。不要为每次正常导航强加确认框。现有数据与副本恢复依赖都须保留。

五 完整人类学习与课程准备

学习首页围绕当前目标、下一步和到期复习。目标详情承接诊断、先修、误区、认知负荷和可解释路线；学习活动包括阅读、记忆编码、主动提取、主动训练、技能实战、Teach-back和错误反馈；结果与画像承接元认知、长期巩固及调整。正式课程不是所有学习活动的前置门槛。普通用户可以直接从知识进入练习/复习，能提供什么活动以实际能力为准。

学习课程页以目标/当前场景/正文与图示/进度/下一动作组织；引用、制作来源、采用状态、资产详情可以折叠。长篇阅读、视频、动画和参数仿真各有适合的承载容器；文本/图文降级保持可读。媒体播放、任务完成、教学采用与实际掌握分别记录。FSRS排程、观看完成、AI点评均不能直接推出掌握。

课程准备作为同一课程/教学项目的上下文视图：教学需求→表达方案→交付→练习→反馈→修订。允许草稿不完整保存；阶段进展显示当前需要的输入，不强迫所有活动线性走完。需求和方案审阅要保留身份、引用版本、用途与改动历史；交付登记和教学采用分开；来自外部生产者的回执不冒充真人学习事件。

学习视图偏重场景和行动，准备视图偏重目标、产物与修订。视图偏好不等于权限；服务端决定实际可读/可写/可执行资格。反馈记录原课程版本、题目和rubric，对未来修订有可追溯关联。学习历史仍指向当时版本，不能因后续修订被覆盖。

六 AI工作区和三项目交换

AI工作区展示项目记忆、知识包、规则技能与经验候选，支持查看来源、用途范围、冲突与修订。候选先可保存，评测与采用后再按资格复用。纠正与复测有原回答、具体错误、修订候选、固定测试和实际结果；复测失败保留差异和后续动作，撤回不改旧回执。可选参数训练独立保留，不是AI基础功能前置条件。

知识侧的AI帮助可以通过对象相关入口进入，并明确可见内容、版本和用途范围。AI不可用时普通笔记与阅读继续工作。有限任务只呈现真实授权范围、步骤/预算、取消/检查点和回执；复杂工作流仍由WORK-LAB承接，不扩张AAOS为总控制后台。

AAOS提供版本化知识和教学需求，DESIGN-LAB提供其专业表达/生产产物，WORK-LAB提供其执行与技术验证结果。首期人工交换清楚标注，允许读取和准备不等于授予执行。导入接收要分别核对生产者身份、版本、用途、hash与幂等；未知/不兼容保留原载荷并给出接收失败原因。索引中的平台/供体数量不能当成真实集成数。

七 导入导出与备份恢复

导入是正常任务流程：选择原件→识别/校验→确认实际支持与损失→保存原件并按能力转换→查看结果。保存原件与转换结果分别确认；批量任务逐项报告，部分失败可只重试失败项。取消时说明实际已持久化对象，不能自动抹除已经保存的内容。导出说明真实范围、格式、绑定版本及损失；单次导入成功不等于双向无损互通。

备份恢复纳入核心可靠性。界面直接读取Core实际返回的备份标识、名称、时间、schema与兼容信息；显示名称和机器标识分离。恢复流程：列表→完整性/兼容性检查→目标和影响预览→对实际覆盖范围明确确认→执行结果→重启回读。先支持既有契约中的可恢复路径，不凭UI发明Core不支持的恢复模式。独立副本恢复优先在验证中承接；真实覆盖动作应按现有数据保护和授权规则处理。

普通保存、草稿恢复、内容版本回退、AI候选撤回、数据库/CAS恢复与同步冲突是独立行为，不能共用一个已恢复灯。失败回执可定位实际操作/备份；重试保持原身份与幂等语义。恢复验证保护原实例，检查知识、原件、引用、版本与草稿的一致性。

八 公共状态与响应式

提示分四处承接：对象保存/引用提示、页面结果和空态、全局运行能力、独立高影响操作对话框。全局网络失效不应铺满每张卡；对象引用过期在当前对象处提示；普通成功提示轻量显示，持久失败有可再次打开的记录。Toast不能替代恢复结果、批量损失、冲突比较和权限原因。

建议窗口规则依据可用内容宽度：主文档阅读空间优先约640px以上，Inspector约280px且可折叠；放不下时收起Inspector，不硬塞三列。1280级窗口允许按实际宽度保留详情；1024级窗口以正文加抽屉为主；更窄窗口简化导航并显式可展开，不能只剩无名称图标和死入口。表格局部横滚，页面主要内容保持纵向阅读；表单必要时单列。桌面尺寸与100/125/150%显示缩放要分别核对。

窗宽变化、主题、Inspector开合只改变布局。列表选中项、滚动、筛选、编辑文本和练习输入应继续保持。深链接进入详情能回到合理上级，没有旧现场时显示普通返回入口。键盘打开/关闭弹窗、Tab循环、Escape、焦点回到触发处与取消行为均由成熟组件承接；输入法组合期间的快捷键不能误触操作。

九 将来实施与成熟度判定

先以实际工作树核对旧路由/行为与已有接口。第一批统一Shell和运行适配器，贯通知识保存、编辑可靠性、正常恢复入口与版本来源。第二批贯通学习目标/路径/课程/真实练习，并保留全能力可发现性。第三批补人工教学交换与AI候选纠正复测，再逐步资源/互通扩展。研究、双链等已有行为继续承接，不以顺序为由移除当前可用能力。

设计收口需有22页新入口映射、真实主要动作、失败/返回/恢复行为及能力细项覆盖。实际实现需证明Core读写、对象身份、编辑可靠性和权限行为。运行验证需覆盖日常离线、窗口/缩放、Tauri/浏览器能力差异、中文输入、重启和失败。安装态、交换、真人试学和长期效果分别保留证据。只完成其中一层时，其他层维持待验证。

第一批可交付的判断：用户能新建并写中文笔记，获得真实保存回执，切主题/换窗口不丢内容，离开和重启能继续，原件与版本可回跳，正常界面可进入备份检查与经过验证的恢复流程，两个宿主使用同一产品页面且差异诚实呈现。所有生产检查当前NOT_EXECUTED。
