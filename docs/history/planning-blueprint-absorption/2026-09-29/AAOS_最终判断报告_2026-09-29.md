# AAOS / ArcheAxis Knowledge 最终判断报告

版本：2026-09-29｜范围：本对话上传历史总包、云端对标、关键源码与 CI 证据的整合深化。

本报告是接手判断与执行建议，不替代仓库 R6/M0 权威，不修改不可变 TaskPack。报告生成前再次读取 GitHub main，仍为 d8f99a6357405054f1f9ee66eb2f88d36f7f5143；本对话两次核对间没有主干变化。

## 1. 最终判断

**AAOS 值得继续沿当前架构推进。现阶段的主要问题是已有模块尚未共同构成经真实用户、真实资料、真实模型验证的完整产品旅程。应把下一轮研发目标收敛为“商业级个人使用体验 + 一条可重启、可纠错、可恢复的真实闭环”。**

现有证据不支持推倒重写、迁回 React/Tauri、再建设通用 Agent 平台，也不支持宣布项目完成。项目已经形成较明确的领域边界和实质代码积累；但真实 Provider、学习掌握度、机器纠错复测、迁移与当前桌面产物验收仍有缺口。

对当前阶段最准确的定性：

| 判断维度 | 最终判定 | 依据与限制 |
|---|---|---|
| 产品定位 | 已收敛 | 本地优先、证据驱动、双向人机学习与可信知识工作空间 |
| 架构方向 | 延续当前方案 | Avalonia/C# + Rust Core/SQLite + isolated Python workers 已被当前权威采用 |
| 历史可追溯性 | 有较完整索引，原件覆盖仍有限 | 本轮核实上传索引与相关仓库记录，未重读全部历史原件 |
| 代码与测试积累 | 有实质进展 | 多个 Core、学习、转换、备份、桌面模块与收据存在 |
| 当前闭环完成度 | 部分完成 | R6 IN_PROGRESS，P0–P5 部分证据，P6 未具资格 |
| 商业级个人使用前端 | 尚未证明达到 | 当前 DLL 的完整交互、DPI/IME/无障碍及真实首用证据不足 |
| Local Green / 发布 | 继续 NOT_READY / FROZEN | 不能以候选包、静态检查或一般 CI 替代安装态验收 |

不提供总完成百分比：任务大小不等，TESTED_LOCAL、合同验证、真实用户运行也不可相加。按链路缺口判断比“完成 80%”更可靠。

## 2. AAOS 应当成为的产品

用户应能把一份资料放进系统，理解系统转换了什么、哪些内容丢失、哪些结论有证据；把认可的知识用于自己的学习和机器任务；纠正错误后看到复测结果；关闭软件后还能恢复同一个工作空间。

核心价值链为：原件保全 → 转换与质量收据 → 引用/证据 → 人工认可的知识版本 → 人类学习与受控机器使用 → 反馈纠错 → 重启和恢复。

三个项目的边界在本报告中仅从 AAOS 已读权威解释：

| 项目 | 与 AAOS 的职责关系 |
|---|---|
| AAOS | 管来源、证据、知识版本、学习状态、AI 资产和受控调用记录 |
| WORK-LAB | 可选外部协调；通用执行器与多 Agent 工作流不成为 AAOS 运行前置 |
| DESIGN-LAB | 可作为设计资产与视觉能力的协作方；AAOS 自身保留正式桌面与学习可视化责任 |

本轮没有重新审计 WORK-LAB/DESIGN-LAB 的当前仓库，因此不据此改写另外两个项目的产品合同。

## 5. 核心缺口及其优先级

### 5.1 Provider 的正式接线是基础缺口

P0 已有契约、局部生命周期测试，正式宿主统一 provider-routing 仍未闭合。需要明确启用、禁用、默认、fallback、health、generation 与失败后状态的一致性。

验收应从桌面操作开始，在 Core/worker 记录中看到实际选择的 Provider；失败后有可解释结果，重启后设置一致，停用后的 Provider 不再被调用。只测试 Python snapshot 解析不够。

### 5.2 学习链必须从“能保存回答”走到“能解释学习状态”

源码 mastery_projection_json 仍明确输出 closed=false。这是对证据边界的诚实表达，不能把布尔值改为 true 来完成任务。

必须先确定掌握度怎样定义：哪个知识组件、哪次测评、答案和评分依据、是否使用提示、哪个知识版本、掌握状态更新与复习排程如何区分。FSRS 可决定复习时机，不能单独证明人已经掌握，也不能证明知识本身正确。

最小验收：真实问题 → 用户作答 → Core Assessment → 可解释评分/掌握状态 → FSRS → 冷重启读回；人工纠错保留版本和来源。

### 5.3 真实模型闭环仍缺运行证据

config/models.yaml 默认仍为 stub/local-stub 与 hash-embedding。该文件不能证明用户机器没有其他模型；本轮也没有访问本机模型库。它说明当前仓库默认配置不足以证明真实推理与语义检索已准备好。

对你的共享模型诉求，接手原则是复用已批准的模型库与一个经验证的服务入口，按角色记录实际可运行模型，避免新建重复模型库、同时部署多套运行器或自动下载大型模型。推理、embedding、reranker 分别验收；此报告不凭旧调研替你锁定新的模型型号或厂商。

P4 至少要记录模型身份、知识版本、输入输出、实际失败、人审 correction、retest 和重启读回；禁止预置 correct=true 或以模型自评代替真实纠错。

### 5.4 前端质量应与核心旅程同步完成

用户提出的“商业级个人使用”属于本轮产品交付要求。仅有可点击导航和测试面板不够，真实路径应具有清晰信息层级、明确操作反馈和可恢复错误状态。

建议将界面验收落在以下用户任务；这是验收组织方式，不新增导航权威：

| 用户任务 | 应看到并完成的结果 |
|---|---|
| 导入材料 | 原件、处理进度、格式支持程度、失败/重试与损失 |
| 阅读与核验 | 原文位置、引用、证据关系、候选与认可状态 |
| 管理知识 | 搜索、版本、来源、编辑与可追踪修改 |
| 学习 | 课程内容、题目、答案、反馈、复习队列 |
| 机器使用与纠错 | 使用了哪些知识、输出错误在哪里、纠错与复测结果 |
| 管理与恢复 | Provider 健康、工作空间身份、备份恢复与诊断 |

视觉与交互验收包括字体/间距/组件状态一致、中文可读性、键盘焦点、命令搜索实际激活、中文 IME、常用 DPI 下无裁切、loading/empty/error/disabled 状态。使用当前构建截图与交互证据，不能用设计稿代替运行效果。

保留 Avalonia 技术方向符合当前权威；本轮没有进行新的 UI 框架横评，不声称已经验证某组件库最优。成熟控件、图标、主题及设计资产可按许可与当前框架兼容性吸收。Web/React 资产可作为设计参考或受限能力集成，不自动构成第二默认宿主。

MainWindow.axaml.cs 达 4,727 行，是职责集中和迭代成本的风险信号；应在业务切片中抽取职责，不先启动全量 MVVM 重写。

### 5.5 迁移与恢复决定数据是否真正可托付

备份测试、候选包完整性和非空真实数据迁移是不同层次。P5 要在隔离 Legacy 副本上验证 workspace identity、原件 hash、关联完整性、语义差异、损失报告、恢复及重启读回。P6 再处理准确目录范围内的 Green 备份、替换与回滚。

这些缺口不能由界面优化或增加模型抵消；真实用户数据操作必须有对应授权与可审阅结果。

## 9. 什么情况下可以判定当前目标完成

对同一份真实资料，能够在当前正式桌面演示完整旅程；引用和知识版本可追踪；真人回答与学习状态可恢复；真实模型错误经人审后能复测；备份恢复与隔离迁移成功；当前候选的源代码、构建输入、制品及测试证据能对应起来。

验收结果必须按实际覆盖分别写出通过、失败、跳过和未验证。只有需要的阶段门通过，才能继续 Green 决策。当前这些条件尚未同时成立。

## 6. 本轮需要纠正或防止误读的事项

### 6.1 状态总账不能代替 main 身份

R6-STATE.updated_at 为 2026-09-26，顶层 subject_sha=2994efa…，delivery_line=main；实际 main 为 d8f99a6…。这不抹去旧证据，但机器读取容易把“历史前端来源状态”解释为当前 main 全部完成度。建议在可变台账明确区分 repository_observed_sha、evidence_subject_sha、runtime_artifact_hash、observed_at。历史 tested SHA 保留，不能统一改成当前 SHA。

### 6.2 未上传的本地前端仍是未知范围

远端前端分支为 43c2caf…；9/26 收据提及 2994efa… 和 10 个 untracked build inputs。主干可包含后来整合的部分代码/记录，但本轮云端读取无法证明用户本地当前未提交文件和候选包全部已同步。必须在本机用 git status、diff、构建输入 manifest 对照，不能直接覆盖本地前端或称“云端就是最新完整界面”。

### 6.3 当前 DLL 必须重新绑定界面证据

R6-STATE A12/A13 已明确：重建 DLL 不继承旧 DLL 的 16/16 路由/UIA 结果；命令输入/结果激活、DPI/viewport、IME、屏幕阅读器、高对比、真实首用仍开放。9/21 UI/VI 资产属于参考来源，不能代替运行截图。

### 6.4 学习链存在写线程等待

源码 review 路由在 with_store → record_review_with_state_and_answer 回调内同步调用 FSRS worker；9/27 架构文档也承认该例外。风险是调度变慢时阻塞其他写操作。建议在真实旅程中测写入延迟，并以状态版本/冲突检测保留正确性后再移动计算；不是简单把事务外移或新增第二写者。

### 6.5 开源吸收的“登记”与“资格化”未闭合

DeepTutor/OpenTutor/LearningMAP/OpenMAIC/RAG-Anything/LightRAG/Graphiti/MemOS 等仍 candidate；多条 exact revision、license 为 UNPINNED/UNVERIFIED。先资格化当前默认闭环真正要用的供体，其余继续候选，避免同时安装多套栈。

### 6.6 UI 可维护性风险

主干 MainWindow.axaml.cs 4,727 行，MainWindow.axaml 810 行。这是职责集中风险指标，不是单凭行数认定功能错误。建议随 P1/P3 垂直切片逐步抽取学习、导入、命令导航等职责，不以全量重写阻断真实闭环。
