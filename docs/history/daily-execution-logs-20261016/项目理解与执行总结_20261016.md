## 项目本质理解

### 这是什么项目？

**ArcheAxis Knowledge OS（星环知识操作系统）**是一个**本地桌面知识工作流系统**，核心定位是：

1. **个人知识管理的可信基础设施**
   - 本地Windows桌面应用（Tauri 2 + React + Rust Core）
   - 原件保全、文档草稿、冲突恢复、搜索检索
   - 支持常见格式（txt/md/pdf/docx/xlsx/pptx/音视频等）
   - 单一作者模式，避免并发写入冲突

2. **人类学习的数字伙伴**
   - 学习旅程管理（课程、目标、作答、反馈、复习）
   - 教学反馈系统（teach-back、评分、修订）
   - AI陪伴但人类主导（小栖角色，但人工确认边界清晰）

3. **有界的AI能力集成**
   - 材料问答、文档检查、对话总结、嵌入式向量
   - 模型配置（loopback本地、API服务、订阅客户端）
   - 明确的"机器候选→人工接受"边界（不自动approved）

4. **研究与表达工具**
   - 双链图谱、研究空间、关系投影
   - 独立草稿、表达编辑、导出分享
   - 引用工作台、版本控制

5. **严格的工程治理**
   - 单一真值来源（权威文档、决策账本、接续记录）
   - 不可变规划包 + 活动执行指针
   - CI/exact-SHA验证 + 隔离运行时资格
   - 供应链账本、来源哈希登记、审计快照

### 项目治理特点

1. **权威文档分层**
   - 平台指令 > Owner明确决定 > AGENTS.md > 规范合同 > TaskPack > 历史证据
   - 活动指针：`docs/current/AAOS-ACTIVE-EXECUTION.json`
   - 路由登记：`docs/current/AAOS-AUTHORITY-ROUTES.json`
   - 决策账本：`DECISION_SUPERSESSION_LEDGER.yaml`

2. **不可变规划 + 可变执行**
   - TaskPack是dated source，不能改
   - 执行进度在`AAOS-UI-FIRST-EXECUTION-20261009.md`等活动记录
   - Owner决定覆盖历史规划

3. **来源可追溯**
   - 所有输入材料有SHA-256
   - ZIP归档有MANIFEST.json
   - 审计快照记录observed_at/SHA/命令/退出码

4. **分支与worktree策略**
   - 一任务一分支一worktree一agent
   - codex/* 命名空间（AAOS工作）
   - astryn/* 命名空间（ASTRYN子项目）
   - 合并后删除分支，保留证据在commits

3. **效果图与规划脱节**
   - 新生成的A01/A02/A03效果图无规划依据
   - 新增"运行与诊断"一级入口无映射

4. **文档复杂度高**
   - 权威分散在多个JSON/YAML/MD
   - 需要遵循resolution_order才能找到真值
   - 新接手agent容易误读旧文档

## 项目价值与设计哲学

### 为什么这样做？

1. **本地优先（Local-first）**
   - 数据主权在用户手里
   - 不依赖云服务存活
   - 离线可用，网络可选增强

2. **可信基础设施**
   - 原件保全（CAS + SHA-256）
   - 草稿隔离（冲突恢复）
   - 审计可追溯（来源哈希）

3. **人类主导，AI辅助**
   - 机器标注→人工确认
   - 不自动accepted知识
   - 明确的决策边界

4. **工程严谨性**
   - 单一真值来源
   - 不可变规划
   - CI exact-SHA验证
   - 隔离运行时资格

5. **长期演进**
   - 权威文档分层
   - 决策可追溯
   - 旧决定可supersede
   - 实验分支独立验证

### 与同类产品的区别

- **vs Obsidian**：更强的AI集成、学习旅程管理、原件保全
- **vs Notion**：本地优先、数据主权、可审计
- **vs Mem/Reflect**：不自动标注、人类确认边界、完整框架
- **vs Roam Research**：桌面应用、格式支持更广、工程治理

## 我的理解是否正确？

基于今天的深度审计和代码阅读，我认为这个项目是：

**一个为个人研究者/知识工作者设计的、严格工程治理的、本地优先的、AI增强的知识操作系统**

核心价值主张：
1. 你的知识，你的数据，你的规则
2. 机器建议，人类决定
3. 可信、可审计、可恢复
4. 长期演进，不锁定供应商

设计权衡：
- 选择了**完整性**而非快速迭代
- 选择了**可审计**而非简单易用
- 选择了**本地控制**而非云协作
- 选择了**单一作者**而非多人并发
