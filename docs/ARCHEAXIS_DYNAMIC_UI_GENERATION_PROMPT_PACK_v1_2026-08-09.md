# ArcheAxis Workspace 动态 UI 生成提示词包 v1

> 用途：将本文件中的提示词发送给其他 AI 模型、UI 生成工具、原型平台或智能体平台，让它们基于项目本身自主推导信息架构、布局、交互与视觉界面。
>
> 核心要求：描述产品与业务关系，不预先写死具体页面排布；生成结果必须是动态、可交互、有状态反馈的产品体验，而不是静态后台模板或单张效果图。
>
> 项目仓库：`https://github.com/DTALEX66/Cognitive-Loop-OS`
>
> 本文件是设计与生成提示词，不是当前功能完成度声明。凡使用模拟数据、规划能力或未接入能力，界面必须明确标注。

设计目标可以覆盖完整产品愿景，但当前实现事实仍以仓库中的 `PROJECT_STATUS.md`、真实代码、测试和运行证据为准。外部生成模型不得把本文描述的目标态自动解释为已完成、已发布或已通过 Windows 安装态资格。

## 1. 推荐使用方法

根据平台能力选择组合：

1. 一般 AI 模型、产品设计智能体：发送“通用母提示词”。
2. 生成某个业务区域：发送“通用母提示词”后，再追加对应的“专项提示词”。
3. 能生成前端代码的平台：最后追加“可运行前端实现后缀”。
4. 能生成高保真原型的平台：最后追加“高保真交互原型后缀”。
5. 只能生成图片的平台：最后追加“视觉关键帧与动效分镜后缀”。
6. 多智能体平台：使用“多智能体协作提示词”，让多个角色共同产出一套一致的产品界面。

不要同时把所有专项提示词都塞给上下文较小的模型。通常使用“母提示词 + 一个专项提示词 + 一个平台后缀”效果最好。

## 2. 通用母提示词

```text
你是一支由资深产品设计师、UX 架构师、交互设计师、视觉设计师、动效设计师和前端产品工程师组成的团队。请围绕下面的真实项目，独立理解产品目标，自主推导合理的信息架构、用户路径、页面体系、布局方式、视觉语言和交互体验。

不要等待我规定具体导航形式、页面列数、卡片数量、按钮位置或组件摆放。布局和结构由你根据用户任务、信息密度、对象关系、工作流阶段和目标平台自行设计。不要机械套用常见的左侧栏后台、数据大屏、ChatGPT 克隆或普通知识库模板。

项目名称：元枢 ArcheAxis Workspace / ArcheAxis OS
代码仓库：Cognitive-Loop-OS
产品定义：一个本地优先、证据驱动的 Human–AI Learning & Knowledge Workspace。
产品主张：同一份知识，人学得更深，AI 用得更准。

这不是单纯的爬虫、文件转换器、笔记软件、RAG 聊天框、在线课程平台、通用 Agent 平台或管理后台。它要把资料搜索、知识摄取、证据治理、人类学习和 AI 复用连接为同一条可追溯、可审核、可恢复的知识生命周期。

当前第一个高保真纵向重点是 Obsidian Vault、Markdown 与 JSON Canvas 的开放格式兼容，但 Obsidian 只是资料来源和兼容层之一，不是整个产品，也不应决定全部界面形态。本文后面描述的是目标产品体验，不代表每项能力现在都已经实现。

产品的长期完整链路是：

学习目标或研究问题
→ 多源搜索与发现
→ 合法、安全、可恢复的资料摄取
→ 原始资料与来源版本保存
→ 多形式、多格式、高保真转换
→ Claim、Evidence、冲突、版本与知识建模
→ 概念、能力与先修关系
→ 课程、课时、示例、练习、测验和多样式学习对象
→ 人类阅读、理解、训练、复习、Teach Back、迁移和掌握
→ 仅使用已审核知识的 AI 检索、引用回答、Prompt、Skill 和机器知识复用
→ 评测、纠错、反馈与持续知识演进。

系统面对的资料不局限于文本。产品范围包括网页、动态网站、站点发现、Feed、API、学术资料、Git 仓库、Markdown、Obsidian Vault、JSON Canvas、PDF、Office 文档、电子书、图片、扫描件、表格、公式、图表、音频、视频、字幕、代码、Notebook 和结构化数据。不同来源和格式可以有不同处理方式，但在用户体验中应汇入同一套来源、证据、知识、课程、学习和 AI 复用关系。

系统有两条共享同一知识底座的主链：

1. 人类学习链：资料 → 理解 → 结构化 → 课程或笔记 → 练习 → 复习 → 掌握 → 应用 → Teach Back → 迁移。
2. AI 使用链：Knowledge Unit → Retrieval → Evidence Context → Machine Knowledge → Task Support → Trace → Evaluation → Candidate Lesson。

两条链不是彼此隔离的。人的纠错、标注、练习结果和审批可以形成新的候选知识；AI 找到的新来源、冲突、解释、课程草稿和任务经验也只能先成为候选，经过审核后才能进入正式知识或运行时。

产品必须坚持以下事实与治理原则：

- Raw-first：原始资料、来源版本和内容哈希不能被转换结果替代。
- Evidence-first：重要结论、课程内容和 AI 回答必须能够回到具体来源与证据锚点。
- Candidate-by-default：外部资料、模型生成物、自动课程和 AI Lesson 默认是 candidate，不自动成为 verified truth。
- 人工可控：审核、批准、驳回、弃用、撤销、回滚和重新验证必须清楚可见。
- 可恢复：搜索、抓取、转换、生成和评测属于可观察任务，应支持进度、暂停、取消、重试、恢复和失败解释。
- 本地优先：在无云账号、无 API Key、离线或缺少重型引擎时，已保存资料、证据、课程和学习记录仍应可用；能力缺失或降级必须明确显示。
- 明确授权：本地优先不等于自动扫描个人磁盘。资料只能来自用户明确选择或批准的范围；当前没有真实写入合同时，不得暗示系统会覆盖、同步或静默修改原始 Vault 和文件。
- Provider-neutral：Crawl4AI、Spider、Crawlee、Scrapy、Docling、PaddleOCR、Whisper、FSRS 等只是候选能力来源。普通用户主要选择“自动、质量优先、速度优先、离线、低资源”等策略，供应商品牌只适合出现在高级诊断、许可证和审计区域。
- 复用优先：优先使用合法、成熟、可替换的开源能力，只有真实评测证明候选都不满足要求时才自研底层能力。
- 准确率可测量：不能用模型信心、宣传文案或单个示例声称准确。界面应让用户理解来源完整性、转换损失、证据覆盖、冲突、不确定性、样本量和评测结果。
- 状态诚实：规划、模拟、未接入、不可用、降级、候选、审核中、已批准、已弃用和已撤销必须区分，不能把未来蓝图伪装成已经完成的功能。

产品可形成一组连贯的工作空间，例如 Discovery、Intake、Conversion Quality、Knowledge Review、Course Studio、Learning Player、AI Reuse 和 Evaluation。这些名称表达业务责任，不是在要求你照搬固定导航或固定页面结构。请根据完整用户旅程自行决定如何组织、合并、渐进呈现或建立上下文关系。

界面首先服务普通学习者、研究者、知识工作者和创作者，同时允许高级用户查看来源、转换引擎、许可证、任务记录、证据链、质量指标和系统诊断。普通用户界面优先使用可理解的名称，不直接暴露数据库字段、内部 command ID、package ID、job ID、绝对路径或底层实现术语。

不要只生成静态页面、单张视觉稿或纯展示型仪表盘。请生成一个真正可操作、可流转、有状态变化并带有适度动效的产品体验。动效必须服务于因果关系、空间关系、任务进度、内容演进和操作反馈，让用户感到知识正在被发现、摄取、转换、验证、组织、学习和复用。

你可以自主设计页面切换、层级进入、内容展开、拖放、排序、筛选、搜索反馈、来源预览、证据回跳、差异比较、知识关系变化、任务流式进度、课程生成、学习反馈、复习调度、AI 流式回答与引用定位等互动。不要机械照抄这些示例，应根据业务语义选择最有价值的交互。

完整考虑初始、空状态、悬停、聚焦、选中、拖放、加载、流式处理中、排队、暂停、重试、成功、失败、部分成功、冲突、离线、低资源、权限受限、来源失效、证据不足、撤销和恢复后的状态。关键按钮和对象应有真实反馈，不要让所有操作都只是装饰。

动效风格应克制、流畅、专业且有解释力。优先使用微交互、共享元素过渡、局部状态变化、进度可视化和关系变化，避免无意义的大面积运动、持续漂浮、强烈闪烁和仅为炫技的 3D。支持键盘操作、清晰焦点、足够对比度、屏幕阅读语义、字幕或文本替代，并支持 prefers-reduced-motion 或等价的低动效模式。

视觉气质应体现可信、深度、秩序、专注、知识感和人机协作感，同时保持现代与有生命力。可以从“曜金本源”或“深空轴心”的名称获得氛围灵感，但不要被现有配色或旧原型束缚。避免廉价科幻、霓虹线条堆砌、脑神经网络背景、过度玻璃拟态和通用 AI 渐变模板。视觉创新必须提高阅读、比较、理解和行动效率。

产品以 Windows 本地桌面体验为重要目标，也可以有响应式 Web 表现。中文优先，必要时保留清晰的中英双语术语。需要兼顾中文长文本、文件名、路径、表格、证据引用、不同屏幕尺寸和 CPU-only 或离线环境。

请先理解产品，再进行设计。你应自行完成：

1. 用简洁语言复述你对项目和核心用户价值的理解。
2. 提出与产品语义匹配的信息架构和关键用户路径，但不要为了输出而堆砌所有模块。
3. 选择最能证明产品价值的关键界面与端到端场景。
4. 建立一致的视觉、组件、状态和交互语言。
5. 说明动效如何表达对象关系、任务状态、证据追踪与学习进展。
6. 生成高保真界面或可运行原型，并覆盖关键异常、降级和恢复状态。
7. 明确哪些内容使用模拟数据，哪些只是未来概念，禁止伪造后端、模型、抓取、转换或评测已经真实完成。

不要宣称完整搜索、整站抓取、全格式无损转换、课程工厂、Human Learning Player、通用 Planner、多 Agent 自治、3D/VR、完整 AI 闭环、公开发布或全部 Windows 安装态门禁已经实现，除非输入中另有同一版本的真实运行证据。历史 UI 页面地图和原型截图只能作为设计词汇参考，不能单独证明当前功能可用。

最终成果应该让人感觉这是一个“正在运行的知识与学习工作空间”：用户能看见知识从来源进入系统，经历证据治理，转化为课程与学习活动，再被 AI 有依据地复用；而不是一组彼此无关的静态后台页面。
```

## 7. AI 有证据复用专项提示词

将下面内容追加在“通用母提示词”之后：

```text
请聚焦设计 ArcheAxis Workspace 的 AI Reuse 体验。这里的核心不是再做一个通用聊天应用，而是让 AI 只在用户许可的范围内，使用已审核、可追溯、版本明确的知识完成任务。

用户需要知道 AI 检索了哪些知识、为什么选择这些内容、每个重要结论引用到哪里、哪些证据互相冲突、哪些来源过期、哪些内容被截断或遗漏。没有足够证据时，AI 应拒答、限定回答或请求用户扩大范围，而不是生成貌似确定的结论。

AI 输出可以进一步形成课程辅助、Prompt、Skill、机器知识或任务经验，但这些产物仍然是可审阅、可版本化、可撤销的资产，不应自动进入 Runtime。任务支持需要显示权限、预算、范围、进度、取消、Trace 和 Evaluation，而不是隐藏执行过程。

请根据以上语义自主设计 AI 与知识、证据、任务和审核之间的关系。避免把整个产品压缩成“左边会话列表 + 中间聊天 + 右边引用”的固定套路。可以使用流式生成、引用聚焦、上下文范围变化、冲突提示和 Trace 展开等动态交互，但必须保持内容可读、可核验和可控制。
```

## 15. 不可省略的生成验收条件

无论使用哪一种提示词，最终结果至少应满足：

- 不是单张静态页面或只有视觉效果的空壳。
- 至少一条核心路径可以连续操作并产生真实状态变化。
- 动效表达业务状态或对象关系，并有低动效替代。
- 清楚区分真实、模拟、候选、规划、不可用和降级能力。
- 来源、证据、审核和 AI 引用关系能够被用户理解。
- 异常、证据不足、离线、失败、暂停、重试和恢复不是被忽略的边角状态。
- 普通用户不被内部 ID、数据库字段和 provider 品牌淹没。
- 没有把模型置信度、演示数据或漂亮图表冒充真实准确率。
- 没有暗示会自动扫描个人磁盘、继承浏览器登录态或未经审核覆盖原始 Vault。
- 布局由生成模型依据项目自行推导，而不是照抄提示词中的业务列表。
- 最终体验呈现的是一个运行中的 Human–AI Learning & Knowledge Workspace，而不是若干模板页面。
