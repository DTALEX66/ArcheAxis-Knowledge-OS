# Character profile and approved memory

BE06 stores one versioned `character_memory_v1` record in Core-owned `workspace_meta`; it creates no second knowledge database. All writes pass through Store and require the human principal. Every command carries workspace identity, restore epoch and revision CAS. Profile fields are preferences and learning goals, never facts or permission grants.

Finite endpoints: human GET/POST `/api/v1/character-memory`, human GET `/api/v1/character-memory/export`, and authenticated consumer GET `/api/v1/character-memory/context`. Native commands mirror these four routes. The context contains only the enabled profile and explicitly human-entered memories with provenance. It declares `human_preferences_only`, no grants and no admitted knowledge. Default is disabled. Chat messages are never automatically remembered. Remember/correct require explicit text and provenance; the consumer cannot invoke those operations as a machine principal.

Forgetting removes the actual entry from the live SQLite record, not just a card. No derived index is built for this memory channel, so no index cache copy requires invalidation. Consumers must obtain a current context snapshot per new request, freeze its workspace/restore/revision with the request, and never reuse an old context after a revision or restore change. Disable emits empty context without deleting the profile. Forget-all deletes all live entries; preferences and goals remain independently editable.

Historical chat transcripts and completed task records remain historical records; forgetting does not rewrite their text. Existing backups retain their snapshot and are not edited. SQLite deleted pages, external copies and backups are not claimed to be securely erased. Export is an explicit local response containing personal memory; it performs no upload. Restoring a backup changes the restore fence, rejects stale CAS, and disables the restored memory profile until an explicit current human enable command. An enable command reapproves that snapshot; read it before enabling.

BE05/ASTRYN integration must consume the separate context port through Core and keep preference/memory separate from evidence-bearing material. No role or relationship style may override fact attribution, source checks, capabilities, grants or human admission. This patch exposes and tests the finite port; companion UI/installed runtime qualification remains a separate integrated receipt.
