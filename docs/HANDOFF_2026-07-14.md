## 4. 启动与操作

### 4.1 开发环境

```bash
python -m pip install -e ".[dev]"
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

访问入口：

- Core API：`http://127.0.0.1:8000/docs`
- Knowledge Dashboard：`http://127.0.0.1:8000/kb`
- Knowledge API：`http://127.0.0.1:8000/kb/docs`
- Health：`http://127.0.0.1:8000/health`

安装后 CLI：

```bash
cognitive-os health
cognitive-os stats
```

### 4.2 生产环境最低配置

必须由部署系统注入独立的强密钥，不得将真实秘密写入仓库：

```bash
export COGNITIVE_ENV=production
export COGNITIVE_AUTH_ENABLED=true
export COGNITIVE_API_KEY='<secret-from-deployment-system>'
export COGNITIVE_JWT_SECRET='<different-jwt-secret>'
export COGNITIVE_CORS_ORIGINS='https://your-ui.example'
export COGNITIVE_DATA_DIR='<writable-runtime-directory>'
```

生产配置不满足安全约束时，应用应拒绝启动，而不是回退到开发默认值。

### 4.3 数据恢复

```bash
python shared/backup.py restore <backup-file>
```

该命令只生成并校验 `restore-candidates` 下的离线候选，不会覆盖活动数据库。实际切换步骤：

1. 停止 API、healthcheck 和全部 worker；
2. 核验候选数据库；
3. 由运维人员离线替换；
4. 启动服务并运行 health、数据完整性和业务冒烟测试。

## 6. 当前真实限制

1. Planner 仍主要编译固定 echo 步骤，不是完整动态规划器。
2. Evaluator 仍主要进行二值评分，缺少多维评估和可信 Lesson 反馈闭环。
3. 旧细粒度 Knowledge Base API 仍保留，路由面尚未真正缩减。
4. `knowledge_base/api.py` 仍有部分遗留领域路由等待继续拆分。
5. Mypy 尚未成为零错误门禁。
6. OCR/ASR 准确率必须依靠人工标注金标准；程序不能自行证明 85–95% 准确率。
7. 本轮机器没有 Docker CLI，因此只完成 Docker 静态合同测试和 wheel 实测，没有声称本地容器实机启动通过。
8. GitHub Actions 对 `actions/checkout@v4`、`setup-python@v5` 有 Node.js 20 弃用提示，但当次 CI 不受影响。
