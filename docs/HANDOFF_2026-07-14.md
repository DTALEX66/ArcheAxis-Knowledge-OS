## 3. 已完成能力

### 3.1 运行时与知识入口

- `POST /run`：route → retrieve → fixed-step compile → permission → registered tool execution → trace → binary evaluation → memory。
- `POST /kb/pipeline`：摄入、提取、标签、摘要、候选事实与索引；不自动证明事实正确。
- `POST /kb/search`：关键词、向量或混合检索。
- `POST /kb/quality`：准确率和处理总账汇总；调用者提供的 evidence 仍为 candidate。
- `GET/POST /sleep-loop?action=...`：有证据约束的无人值守任务循环。
- `GET /health`：实时递归统计 HTTP operation，不依赖手写路由数字。

### 3.2 质量与证据

- 文件级 JSONL 处理总账、SHA-256、指纹恢复和失败重试；
- 原子 Markdown 输出与可恢复多格式目录摄入；
- 人工真值 CER/WER；没有真值时明确返回 `unverified`；
- 文本命中证据、内容质量静态审计和候选开放来源建议；
- caller-supplied evidence 最高只能成为 candidate，不能自动升级为可信事实。

### 3.3 安全与部署

- Core、Knowledge Base 和 Inspiration Research 使用统一鉴权边界；
- 生产模式拒绝关闭鉴权、弱密钥、非法 key 文件和通配 CORS；
- restore 只创建并校验离线候选，不在线覆盖活动数据库；
- n8n、Airflow、LiteLLM、Crawler 等集成不返回 stub 假成功；
- wheel 可在源码目录外安装并启动 Core/KB 路由；
- 运行时数据库、日志、用户知识、模型和缓存不得进入 Git。

## 4. TP1.0 命名与编码治理

### 4.1 Canonical IDs

唯一机器真相是 `config/naming-registry.yaml`：

| 服务 | Canonical ID | Python package | API prefix |
| --- | --- | --- | --- |
| Core Runtime | `core` | `app` | `/` |
| Knowledge Base | `knowledge-base` | `knowledge_base` | `/kb` |
| Inspiration Research | `inspiration-research` | `inspiration_research`；兼容目录 `Inspiration-Research` | `/` |

机器 ID 使用 ASCII；中文和英文展示名只用于 UI、文档和翻译值。历史名称只能作为显式 deprecated alias 保留。

### 4.2 仓库门禁

- `.editorconfig`：编辑器编码与换行合同；
- `.gitattributes`：Git blob/checkout 换行合同；
- `.pre-commit-config.yaml`：提交前扫描 staged index；
- `scripts/check_repository_conventions.py`：统一扫描 worktree、index 或 HEAD；
- `.github/workflows/ci.yml`：CI 扫描 Git HEAD；
- `shared/naming.py`：运行时读取 registry 的共享实现。

普通文本使用 UTF-8、NFC、LF、无 BOM、无尾随空白并以换行结尾；`.bat`、`.cmd`、`.ps1` 使用 CRLF。详细规则见 [`NAMING_ENCODING_CONVENTIONS.md`](NAMING_ENCODING_CONVENTIONS.md)。

### 4.3 Phase 1.1 Facade 与 Architecture Guard

- Runtime Facade 编排现有 route、permission、execute 与 trace，旧 `/run` 保留；
- Knowledge Facade 提供真实 keyword/FTS 查询，旧 standalone 和 mounted 搜索入口保持可比较；
- Research Facade 生成并持久化 `IntakeCard` candidate，修复 `intake_id` 到 SQLite `id` 的映射；
- Research 实现已迁为 wheel 可安装的 `inspiration_research`，旧连字符目录不再保存第二份业务实现；
- Enhancement Facade 只生成内存 summary/card/quality candidate，不写库、不调用网络或 LLM；
- Contracts Facade 保留当前 `app.schemas` identity exports，并发布 `TaskPackV1`、`ExecutionTraceV1`、`EvaluationV1` 与 `LessonV1`；不声明其他对象或旧 JSON Schema 已全量等价；
- Architecture Guard 已进入 CI，使用精确 grandfather 阻止新增路径变异、反向依赖与外部绝对路径硬编码。

## 7. 强制边界

- 唯一开发目标是本仓库 `Cognitive-Loop-OS`；
- 不再扫描、测试、修改或同步外部 `Obsidian-Assistance`；
- 不访问个人 Vault、E 盘或其他项目目录；
- 外部资料与 AI 输出默认进入 quarantine/candidate；
- stub、echo、preview、dry-run、文件存在和置信度不得冒充真实完成；
- 数据库迁移、架构移动、安全修改和依赖大升级必须拆成独立可回滚提交；
- 临时数据只能写入本仓库 `.tmp/` 或明确忽略的测试/构建目录，并在结束前删除；
- 不提交密钥、活动数据库、缓存、用户知识、模型或生成物。

## 8. 当前真实限制

1. Planner 仍以固定 echo 步骤为主，不是动态规划器。
2. Evaluator 仍主要是二值评分，缺少多维 Evaluation 和可信 Lesson 反馈闭环。
3. `knowledge_base/api.py` 仍包含遗留领域路由，旧细粒度 API 尚未收口。
4. `Inspiration-Research` 仍保留 deprecated launcher；调用方应使用 canonical `inspiration_research`。
5. Mypy 尚未成为零错误门禁。
6. OCR/ASR 准确率必须依赖人工标注金标准。
7. 生产容器、反向代理和并发负载尚未完成实机验证。
8. `TaskPackV1` 已完成 KB dataclass、SQLite row 与 Runtime 窄投影 tracer；`ExecutionTraceV1` 与 `LessonV1` 已完成 Runtime/SQLite row adapter；`EvaluationV1` 已完成 Runtime adapter；其他对象、JSON Schema adapter 和旧 SQLite 对象迁移尚未完成。
