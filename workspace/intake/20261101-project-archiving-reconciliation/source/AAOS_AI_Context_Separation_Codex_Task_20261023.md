# AAOS AI 侧上下文管理线路调整 · Codex 执行任务书

> 任务性质：针对现有仓库的定向架构纠偏与必要的最小实现；不是重新立项、全量重构、功能扩张或仅写方案。
> 仓库：`DTALEX66/ArcheAxis-Knowledge-OS`
> 范围：**仅 AI 侧上下文管理线路**。人类侧此前已经调整完毕，**不得修改**。

## 一、必须正确理解的最新 Owner 决定

1. AAOS（星环知识系统）是用户多个项目中的一个产品，不是所有项目的运行总控中心。当前三个项目之外，未来还会持续有新项目及新 AI 软件；本次设计不得把上下文范围硬编码为 AAOS、WORK-LAB、DESIGN-LAB。
2. **跨项目、跨 Agent、跨软件的原始上下文统一管理，完全移交给独立的外部上下文/记忆系统负责。** 包括会话历史、临时任务状态、过程摘要、执行日志、工具轨迹、代码演进以及跨会话接续；AAOS 不自行采集、同步、保存或充当这些内容的中央运行时记忆库。
3. AAOS 只接收**可复用的知识候选**，重点包括 AI 编程时的错误模式、根因、无效尝试、有效修复、正确方向、适用边界、验证证据和可复用规范。通过去重、来源审查、验证和必要人工审批后，才进入 AAOS 已有的可信知识/机器学习资产体系。
4. AAOS 的 AI 侧仍保留自己的**知识消费和学习能力**：检索经过授权的知识、引用证据、发现冲突、纠正、复测、形成 MachineKnowledge / MachineLesson / 规则 / 技能候选等（以现行权威和代码为准）。此次**仅移走外部 Agent 工作流的原始上下文管理职责**，不能错误删除 AI 助手基于当前文档的有限对话上下文，也不能削弱 Human–AI Co-Learning 永久核心。
5. **人类侧完全冻结不动**：人类阅读、编辑、多格式、研究、FSRS、学习卡片、课程、掌握度、知识晋升等既有能力、路由、数据结构和界面都不属于本任务。
6. 外部方案可候选 OpenViking、Hy-Memory / MemHub 或其他成熟系统，但**目前没有授权选型锁定、安装、修改全局 Agent 配置或接入私人原生会话**。采取 provider-neutral（供应商中立）适配合同；不要为“统一”再新造第二套上下文数据库、Agent Runtime 或治理平台。

## 三、唯一目标架构

```text
[现在与未来的任意项目]  [Codex / Claude Code / Qoder / 其他 Agent]
                \                    /
                 \    授权连接      /
             [独立的外部上下文管理系统]
             会话 / 工作状态 / 轨迹 / 差异 / 错误 / 接续
                           |
                  经验提炼（在外部或适配侧）
                           |
             [最小、脱敏、可追溯的知识候选包]
                           |
          [AAOS 已有受控导入 / 候选审核入口]
                           |
              去重 / 证据 / 复测 / 人工接受
                           |
           [AAOS 权威知识 / AI 学习资产]
                           |
             按权限、适用条件只读检索
                           |
                  [后续 Agent 执行]
```

归属边界：
- 外部系统是**原始上下文、会话和过程记忆的唯一责任方**；可跨任意项目扩展，负责自己的保存、检索、淘汰与接续。
- AAOS 是**已批准知识和 AI 学习资产的治理方**，仅接收候选与必要证据的稳定引用，不能直接抓取整份历史会话或复制外部数据库。
- 对外给 Agent 的 AAOS 知识能力优先采取现有有限 API/MCP/适配出口（如果确实存在且已授权）；没有就只补合同或最小适配层，不新增完整的通用 Agent Runtime。
- WORK-LAB 可以是未来的事件/问题上游，DESIGN-LAB 可以是未来的设计技能知识上游；本任务**不修改两仓、不实现两仓连接、不改变其定位**。

## 四、只调整 AI 侧上下文线路的具体要求

### A. 去除职责重叠，而非暴力删功能
- 清点 AI 侧原有“统一跨项目上下文 / 全 Agent 共享记忆 / 跨客户端会话同步”等职责声明及代码路径。
- 将这部分产品职责转为 `EXTERNAL_CONTEXT_PROVIDER` 边界；没有供应商配置时显示未连接/不适用，不伪报可用，也不能 silently fallback 回 AAOS 自建中央记忆库。
- 现有与文档问答相关的**有限请求上下文**、RAG 查询上下文、模型调用会话状态、当前用户在 AAOS 中进行的正常学习对话，属于业务完成所需的短期状态，**不得误删**。与跨工具长期共享记忆严格区分。
- 不迁移、不删除、不覆盖已有真实数据；任何旧字段/旧能力变更需先列依赖、兼容性、回滚和迁移方式。

### B. 定义可替换的外部上下文适配合同
- Provider-neutral，至少定义 `provider_id`、`capabilities`、`namespace/project_id`、`source_app`、`source_ref`、`auth_scope`、`schema_version`、`fetch_status`、`provenance`、`updated_at`。
- 基本能力仅限：**受授权接收知识候选 / 查询候选元数据 / 读取必要的证据引用状态**。跨项目记忆的写入、会话自动捕获、历史全量导入与统一召回属于外部系统，不进入 AAOS 内核。
- 遵守最小权限、显式材料授权、禁止暗中出网、撤权后禁止新增访问；网络失败/超时/撤权/缺失/来源删除必须显式呈现。
- 支持不止一个外部方案的可插拔合同，但**先只提供接口与测试替身，不同时运行 OpenViking、Hy-Memory 等多套后端**。Windows 支持、部署复杂度、模型费用、日志隐私和许可证作为未来选型门槛。

### C. 可复用知识候选包（严格白名单）
只传“候选知识”和必要证据定位。候选包至少能表达：

```yaml
schema_version: 1
candidate_id: "稳定、可幂等的候选标识"
knowledge_kind: "coding_pitfall | root_cause | verified_fix | decision_rule | reusable_procedure | other"
title: "可检索的经验标题"
summary: "脱敏后的简短结论"
problem: "具体现象及背景"
root_cause: "有证据的根因；未知则标 UNKNOWN"
failed_attempts: []
resolution: "实际采取的解决方案；未解决则标未解决"
applicability: "技术栈、版本、环境和前置条件"
contraindications: "不适用情形及已知反例"
evidence_refs:
  - "外部系统可授权读回的稳定引用 / Git commit / diff / 测试回执"
verification:
  status: "PASS | FAIL | PARTIAL | UNKNOWN | NOT_RUN"
  command: "实际执行的原始命令（如可公开）"
  exit_code: null
  artifact_hash: "真实日志或输出的哈希（如存在）"
source:
  provider_id: "外部记忆系统"
  project_id: "项目命名空间，不限三个项目"
  source_app: "Agent / 工具"
  source_ref: "来源引用，不复制整段对话"
governance:
  state: "CANDIDATE"
  reviewed_by: null
  approved_at: null
  supersedes: []
```

字段以现有 AAOS 领域合同映射为准：**能复用现有 Candidate/Source/Evidence/Revision Schema 就复用，不为示例 YAML 创造平行真值或新数据库。** 候选可先普通保存，但不能在未经验证时成为权威经验。来源的撤销和不可用要显式反映，不能伪造证据仍可用。必要时只保存经授权的最小片段，默认不保存全量聊天、提示词、密钥、账户数据、绝对私有路径或完整原始工具日志。

### D. 有门槛的“经验→知识”流程
1. 外部上下文系统选择一个经验事件，提交候选与证据引用。
2. AAOS 在现有入口做 schema/权限/来源/重复/版本/相似度/冲突/适用范围校验；无需强迫普通草稿保存先过外部事实核验。
3. 如果仅有模型自述“已修复”“测试通过”，**没有真实 diff、命令、exit code 和日志，则不得被认定为已验证的通用修复方案**；标注 UNKNOWN/待补证。
4. 区分局部有效、环境限定、可推广、已过时、已被替代；人工接受或现有受治理条件通过后再晋升为 AAOS 可复用的知识/规则/技能资产。
5. 向下游 Agent 提供**任务相关、最小必要、带出处和适用条件**的知识片段；不自动灌入整库、不把“历史经验”当绝对指令、不保证 AI 一定不犯错。
6. 新的验证结果和反例可通过 AAOS 现有知识修订/冲突机制更新；禁止直接覆盖原始来源或静默提升可信度。

### E. 兼容现有 AAOS 真正核心
- 正式宿主仍为 Tauri 2 + React/TypeScript/Vite；Rust Core 仍为 SQLite/CAS 唯一业务写者；Python workers 继续隔离。
- 不新增与 Rust Core 并列的“权威知识写者”；外部上下文系统只持有自己的上下文数据，不直写 AAOS 业务库。
- 保留 Human–AI Co-Learning、Universal Knowledge Foundation、模型服务、科研、证据审查、多格式、人工学习及已批准的 AI 知识学习能力。
- 不改变用户已经认可的主线 UI、窗口结构、菜单、主题、模型配置、共享工具链或其他项目。
- 不借此次调整启动冻结的六项能力、V01、FT01–04，也不擅自恢复其他已延期项目。

## 五、实施顺序与验收

**阶段 1 — 只读核实**：扫描有效权威/生产代码，产出“旧职责 → 新归属”映射与人类侧保护清单，指出确实会改变的文件和接口；避免仅凭历史 Blueprint 执行大改。

**阶段 2 — 最小落地**：优先更新 AI 侧职责合同和必要的适配/知识候选入口；已有服务具备能力则复用。只修改与上下文线路直接相关的代码及现行权威导航，不改写历史记录，不另建一套进度表。如缺乏真实宿主/外部系统，停在稳定接口和隔离测试，不虚报接通。

**阶段 3 — 针对性测试**（必须保留原始 stdout/stderr、退出码、真实 git diff、测试 SHA）：
- AI 原始跨项目上下文不进入 AAOS 产品库；不同项目命名空间不串读。
- 合法候选可幂等接收、再次读取、重启恢复、按现有流程治理；重复与冲突不会自动晋升。
- 无证据/伪造 PASS/缺失 diff 的案例不会变成权威知识；反例、UNKNOWN、撤权和来源不可用被正确保留。
- 权限撤销、网络超时、外部系统离线、不兼容 schema 都不会损坏现有知识。
- 人类侧 FSRS、文档保存、课程/学习、科研、多格式及当前文档对话功能无回归，至少运行受影响的定向合同/回归测试。
- 正式业务写入仍由 Rust Core 唯一持有；无新的双写、全局 Agent 记忆服务或隐藏云端调用。

**阶段 4 — 权威/交付**：在当前有效的权威索引与唯一进度记录中，精确登记此次决定和实际实施结果（PLANNED、PARTIAL、TESTED、BLOCKED 必须区分）；不重写冻结的旧 TaskPack，不以文档更新冒充代码完成。

## 六、严格禁止事项

- **禁止修改人类学习侧**任何行为、产品页面、学习数据与权威定位。
- 禁止扩大成 AAOS 全量重构、三项目重构、WORK-LAB/DESIGN-LAB 开发任务、全局工作流管理器。
- 禁止新增第二套通用上下文中心、第二套真实知识数据库、第二个 AI/Agent Runtime 或私自接管全局配置。
- 禁止自动扫描用户主目录、私人原生会话、密钥、聊天历史；禁止批量上传/删除、后台监听、隐式云同步。
- 禁止为“成功”放宽测试、只改注释/文档宣称修复、将 mock/SDK 存在等同真实部署可用。
- 禁止擅自安装 OpenViking/MemHub/其他 provider、下载大模型、变更 LM Studio 或花费付费 API Token。
- 保留现行的单 writer、项目内证据保全与授权边界；如改动无法与历史数据兼容，先停止破坏性动作并明确报告，不擅自清库。

## 七、最终回报格式（必须完整）

1. **决策纠偏**：用两三句话说明“外部上下文管理 vs AAOS 可复用知识治理”的所有权边界，并写明人类侧完全未改。
2. **影响面清单**：现行代码/接口、历史供体、此次保留与此次改动的精确路径；说明人类侧保护证据。
3. **实际 git diff**：哪些是业务逻辑改动，哪些仅合同/文档；无业务实现时明示仅完成方案或接口。
4. **测试证据**：原始命令、exit code、pass/fail/skipped、日志/回执路径和环境，明确 mock 与真实外部 provider 的差异。
5. **未完成/阻塞/风险**：外部系统选型、Windows 兼容性、安装授权、私人会话权限、数据迁移、模型/费用与未来接入；不得猜测 PASS。
6. **回滚方法**：精确文件与数据兼容性；不得使用危险的全量 reset/clean。
7. **后续独立步骤**：仅列真实待做事项，不自动启动新的实施队列。

## 最终验收口径

本轮成功条件不是“AAOS 已拥有跨软件万能记忆”，而是：**AAOS 的 AI 侧不再承担所有项目/Agent 的原始上下文集中管理；其 AI 知识与双向学习能力保留；通过严格的候选知识边界允许未来外部上下文系统向 AAOS 输送经过治理的可复用经验；人类侧功能与数据不变。** 如没有授权的真实外部系统，则外部连接状态必须是 `NOT_CONNECTED`，不能宣称已经跨工具同步。
