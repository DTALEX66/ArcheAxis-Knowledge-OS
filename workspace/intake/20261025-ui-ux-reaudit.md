# 2026-10-25 UI/UX 复审：人物、首次使用与完整能力发现

性质：本轮 Owner 请求的审计、改进规格与实施回执，不是新权威或第二份进度账本。当前进度仍归 `docs/current/AAOS-UI-FIRST-EXECUTION-20261009.md`。保留接手时全部 dirty 改动；后续已修改产品源码并构建隔离候选，没有修改模型设置或替换 Green 程序。

阅读顺序：下文审计结论描述改造前状态；文末“本轮实施回执”记录改造后的实际结果，不能将改造前问题或实施计划当作当前状态。

## 1. 结论

界面仍不够好，主要因为此前的改动集中于外壳材质、字号压缩和装饰，任务引导、人物呈现及能力信息层级没有一起完成。现有顶部菜单、浮动主窗、右栏和 Dock 可以保留；继续叠加粒子或降低面板透明度不能解决这些核心问题。

- **人物小有直接实现原因**：全局陪伴窗口使用 `slot="sidebar"`，头像实测 48×48 CSS px。1696×2528 的全身竖图再按 `contain` 装入正方形，其中非透明人物横向约 17px，脸部自然难以辨认。窗口大不等于人物大。
- **人物美感还涉及素材适配**：九张图的正侧身、构图、人物占比和边缘处理不统一；日常居家装与当前科幻知识工作台的视觉语言有距离。这是本轮审美判断，不能作为普遍审美事实。仅放大现有全身图仍会暴露边缘和切换不连贯的问题。
- **首次全流程引导没有实现**：设置内只有五条静态说明，内部可执行按钮／链接为 0；没有首次触发、按实际任务推进、跳过／恢复与完成判断。
- **能力没有按用户理解的方式完整展现**：当前正式目录的 16 个大类和 186 条设计细项都能找到；但主界面只显示大类，细项需逐类进入详情。“未来规划”只包含 6 个整个大类均为 `not_implemented` 的条目，其他已有部分实现大类里的未来内容不会出现在该分类。
- **可读性与空间利用失衡**：全局 UI token 被后续规则覆盖成 12px；主窗默认宽 64vw、高约 60vh，1920×1080 下主窗约 1229×648。复杂流程在有限高度内嵌套滚动，背景与空白占据较多视野。

## 5. 人物在当前阶段如何深化

建议先完成适合桌面知识工作台的2D人物版本，沿 AAOS 内的既有 renderer／共享会话深化；复杂3D、跨软件人格运行时等继续按现行范围处理。

1. **形象规范**：保留小栖身份，产出同一脸型、发型、服装、光源、视线和配色的角色设定；推荐与品牌一致的简洁知识伙伴／轻科幻风格。现有素材作为来源与回退，不直接覆盖。
2. **专用人物构图**：主展示用胸像或半身，头像另用面部裁切；禁止继续用一张带大留白的全身图兼任所有尺寸。先让脸和姿态清楚可见，再判断美感。
3. **三个可控尺寸**：1920×1080的默认人物视觉高度目标240—320px；展开模式320—420px；小窗口紧凑展示160—220px。以上是设计目标，尚未实现／验收；人物不能覆盖正文，来源检查器与大人物模式按需切换。
4. **先补交互角色**：明确现在在看哪份资料、能帮什么、执行到了哪一步；提供“解释当前段落／提问检查理解／生成学习候选”等上下文动作，全部复用现有对象和权限链。
5. **再做连续表现**：同身份表情与姿态过渡、轻量入场和反馈优先；若要眨眼／口型，应有合适的分层或帧素材与真实状态驱动。不能用“正在说话”的静帧冒充语音播放。
6. **语音单独验收**：录音、转写、TTS、播放、打断、设备失败与隐私开关分别验证后再增加；当前仅做视觉改进并不依赖语音或更大模型。

## 6. 首次引导与能力展示规格

首次体验采用可跳过、可返回、可恢复的任务式引导。可使用首次一次性面板或帮助入口重开，不恢复上一轮被否定的永久首页引导条。

首次成功路径：选择目标→导入自己的资料或选择明确标记的内置示例→打开并确认保存→对当前资料提问（模型未配置时允许跳过）→纠正／保留候选→选择进入知识或学习。普通保存和阅读无需模型或知识审批。

后续扩展步骤包括公开研究与来源比较、AI候选批准后的按权限复用、学习复习、重开和导出／恢复。每一步绑定当前对象、版本和真实任务结果；不能把点过“下一步”记作业务完成，也不能把完成向导称为 CL-01—07/J1—6 全部通过。

能力展示采用同一目录的三层阅读：用途全景→具体细项→当前入口与证据。每个细项同时展示“现在能做什么”“尚缺什么”“替代方式”“本期／后续”，提供明确的完整目录入口。需要新状态字段时修改原声明／投影合同，不在页面另造手填真值表。
