## 1. Visual Theme & Atmosphere

保留深空背景、顶部应用菜单、内缩浮动主窗、右侧人物／来源窗口与底部胶囊Dock。目标是清楚、安静、可读的个人知识工作台，具有适度科幻气质。

密度采用日常应用水平5/10；差异来自主次内容与人物角色，而非不断叠加装饰。新手每次只面对一个明确主动作。舒适密度与紧凑密度共用页面、对象、路由和权限链。

人物是当前资料的知识伙伴，有足够大的半身展示和简短状态反馈。人物、会话管理与来源检查分别有清楚区域；展开人物时可切换右栏用途，正文与来源入口始终可达。

## 2. Color Palette & Roles

沿现有批准的 Aether / cosmic palette，不擅自换为暖色极简或新的营销视觉。

| 角色 | 颜色 | 用途 |
|---|---|---|
| 深空画布 | `#0e141d` | 知识工作区底色 |
| 阅读面 | `#161c25` | 稳定正文与表单承载面 |
| 浮层面 | `#1a2029` | 弹层与次级工具区 |
| 主要文字 | `#dee2f0` | 正文与关键标题 |
| 次要文字 | `#bdc8d1` | 辅助说明与元数据 |
| 结构边界 | `#3e484f` | 轻边框和分隔线 |
| 交互主色 | `#8ed5ff` | 主要动作、选中与焦点 |
| 错误 | `#ffb4ab` | 失败／错误语义 |

原设计的青色／青绿token仍可保留语义用途，不用多色按钮争夺主动作。玻璃采用阅读面、工具面、窗口边界三层材质，不用全透明面板直接承载密集正文。背景细节在正文背后局部减弱；保持原图和主题切换。

五主题继续从既有语义token解析。辅助材料不能以技能默认的“禁Inter／禁所有蓝色／持续循环动画”等通用偏好覆盖 Owner 已选设计。

## 3. Typography Rules

保留现有字体来源，Windows中文由系统中文字体可靠回退；不为此下载外部字体。当前参考中的 Inter 可保留，不强行更换所有字体。

- 页面标题20—24px / 28—32px，半粗；区域标题16—18px / 24—28px。
- 正文与主要控件14—16px / 22—26px；辅助说明12—13px / 18—20px。
- 数字／工程诊断在诊断区采用等宽与tabular数字；日常界面使用自然中文。
- 段落控制阅读宽度，长中文标题可换行。不要通过全局12px解决空间问题。
- 字体、间距、密度使用同一组有命名的token；清理冲突规则应按具体切片验证，不批量改主题文件。

## 4. Component Stylings

**人物展示**：主展示使用独立半身构图，脸部清楚、边缘干净；静态fallback仍可工作。宽屏默认视觉高度240—320px，展开320—420px；1280×720紧凑展示160—220px。脸部头像64—80px只用于收起／会话列表。以上均为拟议目标，须实际对照验收。

**角色设定**：沿小栖身份统一脸、发型、服装、光线、视线和构图。推荐简洁知识伙伴与轻科幻细节；九态使用同一设定，避免每种状态像不同照片。原始素材和来源记录保留。

**陪伴空态**：一条清楚说明和“开始提问／解释当前资料”主动作；有材料时展示绑定资料。会话目录、重读历史和工程诊断移至次级操作。未知请求不允许另开替代请求绕过原屏障。

**按钮与输入**：每页／每个任务区域一个主动作；次要动作用轻边框或文字。桌面常用按钮目标高度36—40px，触摸／粗指针目标44px。标签在输入上方，错误紧邻字段；禁用原因可读。

**状态**：空态告诉用户怎样开始；忙态显示当前阶段与取消；失败有原因、原对象和恢复入口；未知状态明确等待核对。技术诊断继续集中，不在正常界面堆叠内部协议名。

**能力条目**：名称→用途→现在能做什么／尚缺什么→具体入口。父类的实现声明不能代替子项状态；不显示虚构完成百分比。

## 5. Layout Principles

- 主壳保持原顶部菜单＋浮动主窗＋右栏＋Dock；不改成侧栏应用，也不新建第二套桌面布局。
- 保留浮动模式，同时让“展开工作区”可发现；按内容密度使用更多可用高度，避免所有业务固定为60vh。
- 右栏包含人物展示、对话与来源三种用途，按任务切换；大人物模式不压缩成48px头像，也不叠在编辑正文上。
- 常用任务留在Dock，完整发现通过启动台／目录；提供文字明确的“查看完整能力目录”动作。
- 能力浏览从用途全景进入186条细项；搜索结果显示命中的细项及父类，不只返回一个笼统大类。
- 未来分类涵盖已有部分实现大类中的未来细项。分类与状态从现有声明／合同投影，不能页面手抄另一份能力真值。
- 1920×1080、1440×900、1280×720、960×720按各自可用空间重排；这些是桌面CSS窗口测试，不自动宣称手机适配或Windows系统缩放已验收。

## 6. Motion & Interaction

只在进入、切换、任务反馈和状态变化上使用克制动效；transform／opacity为主，150—220ms作为待实测起点。支持中断，不在带backdrop-filter的窗口本体进行scale／rotate入场，改由内层动效容器承载。

尊重减少动态、减少透明度与高对比；粒子和持续装饰可关闭。阅读期间不强制所有组件循环跳动或发光。眨眼／口型需合适素材与真实状态，语音、连续动画、设备播放与中断分别验收。

首次体验以可跳过、可恢复的任务面板开始：

1. 选择目标与材料来源，说明本地保存；允许先不配置模型。
2. 导入资料／内置示例→打开阅读→确认保存，用真实对象结果判完成。
3. 对当前资料提问；显式沿现有授权预览与请求链，无模型可跳过。
4. 纠正／保留候选；普通笔记保存与专业知识批准分别解释。
5. 进入知识／学习，后续提示研究、按权限复用与导出恢复；展示已完成、跳过和待办。

不得恢复永久首页引导条。设置／帮助允许重新打开；新用户进度绑定工作区与真实对象，点击“下一步”不能伪造业务完成。完成首次体验不等于正式闭环资格。

## 7. Anti-Patterns & Acceptance

### 2026-10-26 Stitch复审生成约束

本轮继续使用上述统一设计规格提示Stitch，不建立另一份设计真值。实际读取项目 `10243059433218383839` 的「AAOS 交互整合版」，生成复审对照稿并逐项勘误；[协同复审](../20261026-stitch-ui-audit.md)记录来源与限制。

- 系统菜单与Dock放全局入口，窗口Tab只表达已开视图；溢出收纳不删除多窗口能力。
- 默认人物区优先呈现现有人物与对当前材料的帮助，会话重读/新建/历史收纳但可达。宽屏主展示240–320px目标仍须新候选实测。
- 保留可跳过/恢复的现有10步引导；不再复制常驻五步横条、另一份进度或自动完成声明。
- 空工作区不放虚构论文、数量、同步/模型状态、工程版本或能力ID。设计原型无源素材时只能明确占位，产品继续使用已选真实素材。
- Stitch建议的P0等标签不自动成为产品事故等级；图像3840×2160不当作1920×1080 CSS实际通过。菜单至少14px仍为既有验收，不降低标准。

禁止用全身图兼任所有尺寸头像、把人物窗口当会话管理表单、把静态九态说成语音／动画、只加粒子解释美感、用12px统治正文、以父类已实现隐藏子项未来规划。

禁止复制第二份能力注册表、改路由来迁就截图、清空用户草稿／偏好、以虚构百分比表示能力完成、将设计稿视为部署或Owner验收。

每个切片交付同条件前后截图、实际字号与人物尺寸、键盘／焦点结果、空忙失败未知状态、已用素材来源与回退。定向检查通过后再重建Host；浏览器、原生宿主、安装与Owner分别验收。
