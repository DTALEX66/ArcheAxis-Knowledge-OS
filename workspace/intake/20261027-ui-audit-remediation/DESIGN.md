# 星环知识系统：2026-10-27 审计修复设计说明

本文件记录本轮实现取舍，不替代活动指针、命名合同、能力目录或唯一执行记录。输入为 Owner 指定的「对抗审计界面设计」会话及本地 24 条发现；截图评审、组件测试、原生运行和 Owner 验收分别记录。

## 1. 体验与氛围

保留已选 Stitch 桌面结构和五主题。首屏回答「我在处理什么、正文在哪里、下一步是什么」。阅读、编辑和讲解使用连续的内容舞台；参数、内部来源登记和诊断按需展开。面板使用中性玻璃层次，减少蓝色实心卡片和重复边框。

## 2. 语义颜色与材质

沿用现有设计系统的 `--ax-*`、`--stitch-*` 语义变量，主题共用布局。强调色用于当前选择和主要动作，规划状态使用低强调文本及虚线区分，不能以绿色状态暗示尚未实测的可用性。正文以稳定底层保证对比；菜单、引导弹层使用不透内容的背景。玻璃用于外框，不能牺牲阅读清晰度。

## 3. 字体与信息层级

沿用现有 Windows/CJK 字体栈；菜单遵守现有至少 14px 的验收要求。对象标题优先显示可读名称和必要版本。编号、指纹、工程阶段名保留在属性或诊断中。保存状态必须指明所属对象，正文保存与日志待确认等状态仍分别呈现。

## 4. 组件与交互

复用现有 Radix、Tiptap、Driver、Dockview 和图谱组件，不引入第二套 UI 框架。Tiptap 关闭运行时样式注入，编辑器基础样式随程序打包，保持桌面 CSP。折叠及页签调整应保留有草稿的组件挂载和独立草稿标识。右键菜单围绕当前对象；全局导航由菜单和命令面板承担。未实现能力只提供规划浏览及接入条件。

## 5. 布局与导航

Owner 本轮审计修复覆盖旧的展示分组：日常工作收敛为工作台、知识、学习、研究专题、AI、资源六个入口，能力与设置作为独立入口，保留全部 22 个页面深链接。教学在学习路径中进入，顶部菜单仍提供教学相关页。研究独立；历史属于知识；设置不混入研究。旧规划 CSV 作为历史输入保留。本说明不扩大业务实现范围。

1920×1080 为主要展示目标，同时检查短窗口、1366 宽度与放大场景。顶部导航与 Dock 保持可操作；主工作窗口尽量使用二者之间的高度。陪伴、专注、对照是明确的布局选择；普通渲染不重置用户手动几何。阅读默认隐藏次要属性，以正文占据中心。资源先提供已接入模板，供体清单在详情页签中保留。

## 6. 动效与反馈

遵循现有 motion/reduced-motion 机制，聚焦菜单展开、切换、悬停、按下及加载反馈。人物呈现、隐藏和布局切换不能中断会话或丢弃草稿。新人物素材须实际下载、检查透明边缘、循环接缝和状态覆盖后才替换，不能用远端自述代替验收。

## 7. 避免的模式与验收

避免多层卡片套卡片、首屏长篇治理说明、工程参数先于正文、空检查器重复占位、规划按钮伪装执行、切页解除其他页面草稿保护。首次引导以导入、阅读、保存三步开始，完整十步参考可展开；手动勾选不代表业务成功。

统一验证需在写集冻结后绑定实际候选，分别记录类型检查、定向测试、完整检查、原生操作、截图和仍未验证项。原始失败证据不以修复后的定向通过替换。
